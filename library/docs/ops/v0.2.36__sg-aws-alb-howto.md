# `sg aws alb` — how-to

Everything you can do today with the ALB CLI, in the order an operator usually
hits things: stand a stack up, register targets, verify, tear it down.

The command tree:

```
sg aws alb lb        list | show | create | delete | tags
sg aws alb tg        list | show | create | delete | register | deregister | health
sg aws alb listener  list | show | create | delete
sg aws alb stack     provision | destroy | describe
```

All mutating commands (`create`, `delete`, `register`, `deregister`,
`provision`, `destroy`) are gated on `SG_AWS__ALB__ALLOW_MUTATIONS=1`.

---

## 0. Prerequisites

```bash
export AWS_REGION=eu-west-2
export SG_AWS__ALB__ALLOW_MUTATIONS=1        # required for every mutation below
```

You also need a working VPC with **two public subnets in distinct AZs**
(internet-facing ALB requirement). If you don't have one yet:

```bash
sg aws ec2 vpc create-stack --name my-net --yes
```

Grab `vpc_id` and `subnet_ids` from the output (or `sg aws ec2 vpc show-stack
my-net`).

---

## 1. Quick start — one-command stack

The fastest path is `stack provision` — it creates two security groups, the
ALB, a target group, and a listener in one phased run:

```bash
sg aws alb stack provision \
    --name my-app \
    --vpc vpc-0abc \
    --subnets subnet-aa,subnet-bb \
    --yes
```

Output is a Rich-rendered phase table plus a summary panel with the LB DNS
name. Same shape as `sg aws ec2 vpc create-stack`.

What's created (named by convention so re-runs are idempotent):

| Resource | Name |
|---|---|
| ALB | `my-app-alb` |
| Target group | `my-app-tg` |
| ALB security group | `my-app-alb-sg` (80/443 from 0.0.0.0/0) |
| Target security group | `my-app-target-sg` (ingress from alb-sg on 8080) |
| Listener | HTTP :80 → forward to TG |

Defaults baked in:

- Listener: `Protocol=HTTP`, `Port=80`
- Target group: `Protocol=HTTP`, `Port=8080`, `TargetType=instance`
- Health check: `HTTP`, port `8080`, path `/info/health`

Override the ports with `--lb-port 80 --target-port 8080`. Switch the target
type to IP-based (Fargate-friendly) with `--target-type ip`.

### Re-running is safe

`stack provision` finds existing resources by name. Re-running with the same
`--name` prints `SKIPPED` on phases that already exist — no duplicate ALBs
charged.

### Describe and destroy

```bash
sg aws alb stack describe my-app
sg aws alb stack destroy  my-app --yes
```

`destroy` walks the phases in reverse (listener → tg → lb → sgs).

> **Cost reminder.** ALBs are billed per-hour the moment they exist (~$18/mo
> idle). For ephemeral vault sessions, keep **one persistent ALB** and just
> register/deregister targets on a single TG — TGs and listeners are free.
> See [plan][plan-cost] for the LCU breakdown.

## 2. Per-resource recipes

Use these when you want manual control or when you're integrating with an
existing ALB.

### Load balancers

```bash
# Inventory
sg aws alb lb list
sg aws alb lb list --json

# Show one (accepts ARN or name)
sg aws alb lb show my-app-alb

# Create
sg aws alb lb create \
    --name      my-alb \
    --subnets   subnet-aa,subnet-bb \
    --sg        sg-0123 \
    --yes
# Add --internal for internal scheme (default: internet-facing)

# Delete
sg aws alb lb delete \
    arn:aws:elasticloadbalancing:eu-west-2:…:loadbalancer/app/my-alb/abc123 \
    --yes

# Tags (read-only today — add/remove planned)
sg aws alb lb tags <lb-arn>
```

### Target groups

```bash
sg aws alb tg list                        # all TGs in the account
sg aws alb tg list --lb-arn <lb-arn>      # TGs attached to one LB
sg aws alb tg show  <tg-arn>

# Create — defaults: protocol=HTTP, port=8080, target-type=instance,
#                    health check HTTP /info/health on 8080
sg aws alb tg create \
    --name   my-tg \
    --vpc    vpc-0abc \
    --port   8080 \
    --target-type instance \
    --yes
# Use --target-type ip for Fargate / IP-based targets

sg aws alb tg delete <tg-arn> --yes
```

### Register / deregister targets

```bash
# EC2 instance target (target-type=instance)
sg aws alb tg register   <tg-arn> --target i-0a1b2c3d
sg aws alb tg deregister <tg-arn> --target i-0a1b2c3d

# IP target (target-type=ip — e.g. a Fargate task's ENI private IP)
sg aws alb tg register   <tg-arn> --target 10.0.1.42 --port 8080

# Health
sg aws alb tg health <tg-arn>
sg aws alb tg health <tg-arn> --json
```

Target health states you'll see: `initial` → `healthy` (or `unhealthy` with
a reason like `Target.Timeout`). Healthy usually takes **~30–60 s** with
default health-check timing.

### Listeners

```bash
sg aws alb listener list --lb-arn <lb-arn>
sg aws alb listener show <listener-arn>

# Create — port 80 HTTP forwarding to the target group
sg aws alb listener create \
    --lb-arn <lb-arn> \
    --tg-arn <tg-arn> \
    --port   80 \
    --yes

sg aws alb listener delete <listener-arn> --yes
```

Listener rules (path-based, host-based) are **deferred to v2**. v0.2.36 only
supports the default forward action.

## 3. End-to-end walkthrough (EC2 backend)

Sequence to expose an EC2 instance on `:8080` behind an internet-facing ALB:

```bash
# 0. Gate + region
export AWS_REGION=eu-west-2
export SG_AWS__ALB__ALLOW_MUTATIONS=1

# 1. Stand up the stack
sg aws alb stack provision --name my-app \
                            --vpc vpc-0abc \
                            --subnets subnet-aa,subnet-bb \
                            --yes

# 2. Register an EC2 instance that's already running on :8080
TG_ARN=$(sg aws alb stack describe my-app --json | jq -r .tg_arn)
sg aws alb tg register $TG_ARN --target i-0a1b2c3d

# 3. Wait for the target to go healthy (~30–60s)
sg aws alb tg health $TG_ARN

# 4. Grab the ALB DNS name and curl it
LB_DNS=$(sg aws alb stack describe my-app --json | jq -r .lb_dns_name)
curl http://$LB_DNS/info/health

# 5. Tear it all down when you're done (cost: ~$0.025 per hour the LB exists)
sg aws alb stack destroy my-app --yes
```

The LB itself takes **3–5 minutes** to reach `active` after creation — that's
AWS, not us. The `curl` in step 4 may need to wait a beat after `provision`
returns.

## 4. Fargate target pattern

For Fargate tasks (target-type=ip), the IP comes from the task's ENI:

```bash
# Find the ENI
TASK_ARN=$(sg aws fargate task list --cluster my-cluster --json | jq -r '.[0].task_arn')
TASK_JSON=$(sg aws fargate task describe $TASK_ARN --cluster my-cluster --json)
ENI_ID=$(echo $TASK_JSON | jq -r .eni_id)

# Resolve to private IP
ENI_JSON=$(sg aws ec2 eni show $ENI_ID --json)
PRIVATE_IP=$(echo $ENI_JSON | jq -r .private_ip)

# Stack must be provisioned with --target-type ip
sg aws alb tg register $TG_ARN --target $PRIVATE_IP --port 8080
```

The plan suggests folding this lookup into an `ALB__Fargate__Target__Helper`
in a follow-up so callers don't have to wire it manually.

## 5. Verification — `stack perf-test`

`sg aws alb stack perf-test` runs an end-to-end smoke test in one phased
command: provision a throw-away stack → wait LB active → register an
existing IP → wait healthy → HTTP-probe through the ALB → destroy the
stack. It is the executable acceptance gate for the rest of this how-to.

```bash
# 0. Prerequisites (see §0):
export AWS_REGION=eu-west-2
export SG_AWS__ALB__ALLOW_MUTATIONS=1

# 1. Walk-through against an existing target IP (must already be serving
#    HTTP 200 on /info/health:8080 from inside the VPC).
sg aws alb stack perf-test \
    --vpc        vpc-0abc \
    --subnets    subnet-aa,subnet-bb \
    --target-ip  10.0.1.42 \
    --target-port 8080 \
    --http-path  /info/health \
    --time --yes
```

Expected Rich output (truncated):

```
                  perf-test — perf-7f3a2c91
  Status  Phase             Elapsed   Detail
  ok      PROVISION           4.2s    lb=arn:…/perf-7f3a2c91-alb tg=arn:…/perf-7f3a2c91-tg
  ok      WAIT_LB_ACTIVE    184.1s    attempts=37 state=active
  ok      REGISTER_TARGET     0.4s    target=10.0.1.42:8080
  ok      WAIT_HEALTHY       41.7s    attempts=9 state=healthy
  ok      HTTP_PROBE          1.8s    3/3 probes returned 200
  ok      TEARDOWN            3.1s    destroyed
  -       Total            235.3s

perf-test ok — reach: http://perf-7f3a2c91-alb.eu-west-2.elb.amazonaws.com/info/health
```

Flags worth knowing:

- `--keep` leaves the stack in place on success (useful for triage; remember
  to `stack destroy` manually afterwards — the LB keeps billing).
- `--http-probes N` — default 3 sequential GETs through the ALB DNS.
- `--expected-status` — defaults to 200; perf-test fails on any mismatch.
- `--lb-active-timeout` / `--healthy-timeout` / `--http-timeout` — second-
  level knobs for each phase (defaults 360 / 90 / 30).
- `--json` emits a machine-readable `Schema__ALB__Perf_Test__Report`
  (round-trips through `from_json`).
- Exit codes: `0` = all probes match `--expected-status` and teardown
  clean; `1` = any phase reported `ERROR`; `2` = teardown completed but
  left orphans (rare — populated from `report.rollback_errors`).

Design notes live in
[`team/comms/briefs/v0.2.36__aws-alb-perf-test.md`][perf-brief] and the
implementation in
`sgraph_ai_service_playwright__cli/aws/alb/service/ALB__Perf_Test__Runner.py`.

## 6. What's not in v0.2.36

- **HTTPS / ACM** — no listener-on-443, no cert attachment. Vault containers
  serve plain HTTP on 8080; TLS for bare-IP access is a separate problem.
- **Listener rules** — only the default forward action; no path/host routing.
- **NLB** — Network Load Balancers are a separate sibling module (`aws/nlb/`)
  that doesn't exist yet.
- **ECS Services** — `register_targets` is used directly. No
  `create_service`/`update_service` integration.
- **Tag add/remove on LB** — `lb tags` is read-only. Plan tracked under
  Slice 2 follow-ups.

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Mutation gate` panel printed, `Exit 1` | `SG_AWS__ALB__ALLOW_MUTATIONS` not set | `export SG_AWS__ALB__ALLOW_MUTATIONS=1` |
| `ValidationError: At least two subnets in different AZs` on `lb create` | Only one subnet, or both in the same AZ | Pick subnets from distinct AZs (`sg aws ec2 subnet list`) |
| `lb create` succeeds but `curl` hangs | LB still `provisioning` | Wait 3-5 min; `sg aws alb lb show <name>` should report `state: active` |
| `tg health` shows `unhealthy` / `Target.Timeout` | Backend not listening on :8080, or target-sg blocks the alb-sg | Check the backend is bound to `0.0.0.0:8080` and the target's SG allows ingress from `<stack>-alb-sg` |
| `Stack already exists` on re-provision | Stack with the same `--name` already there | Use `stack describe <name>` to verify and `stack destroy <name>` if you want a fresh one |
| `stack describe` shows `target_sg_id: —` | No ec2 client wired (rare — only in test setups) | Run `provision` from the CLI rather than via in-memory test harness |
