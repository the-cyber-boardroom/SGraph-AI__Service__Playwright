# Spec — `pw_capture` stack

> **PROPOSED — does not exist yet.** This is a contract, not a reality-doc claim.
> Every file path under §6 is a proposed layout. The MGraph-AI mitmproxy service
> additions in §5 are PROPOSED for that external repo and must be ratified there.

`pw_capture` is a **new SG/Compute spec** that launches **sg-playwright behind a
mitmproxy data-plane proxy**, with a **bundled interceptor script** that streams
captured traffic to **`MGraph-AI__Service__Mitmproxy`** — the durable,
Lambda-backed control plane (flow store + interceptor registry + egress policy).

It is **additive**: it does not replace the `agent_mitmproxy` sidecar
(`sg_compute_specs/mitmproxy/`), the `sp vnc` stack, or the vault-app egress
proxy. It is the first stack where mitmproxy is wired to an **external,
persistent backend** rather than capturing flows that die with the EC2 host.

---

## 1. Why this stack exists — the gap it closes

Today there are three mitmproxy stacks in this repo, and all three are
**ephemeral / standalone**:

| Existing stack | mitmproxy image | Interceptor model | Flow durability |
|----------------|-----------------|-------------------|-----------------|
| `agent_mitmproxy` sidecar (`sg_compute_specs/mitmproxy/`) | custom (admin FastAPI + 3 addons) | read-only `GET /config/interceptor` | stdout NDJSON (`Audit_Log`); no store |
| `sp vnc` (`…__cli/vnc/`) | vanilla `mitmproxy/mitmproxy:10.4.2` | N5 `NONE`/`NAME`/`INLINE` | **none — flows die with EC2 (rule "N4")** |
| `sg va --with-playwright` (`…/vault_app/`) | vanilla `mitmproxy/mitmproxy:latest` | `Vault_App__Interceptor__Resolver` (`none`/`inline`), hot-reload | none |

The recurring limitation is **N4: captured flows are not exported.** `pw_capture`
closes it by giving the interceptor a **control-plane backend** to push to and
pull from. The MGraph mitmproxy service becomes the system of record for:

1. **Interceptor registry** — named, versioned interceptor scripts (generalises N5).
2. **Flow store** — durable, queryable, HAR-exportable capture.
3. **Egress policy** — allow / block / redact / log rules the interceptor enforces.

## 2. Topology — data plane vs control plane

```
        EC2 node (one pw_capture stack)            external (Lambda / its own EC2)
  ┌───────────────────────────────────────┐      ┌────────────────────────────────┐
  │  sg-playwright  :8000                  │      │  MGraph-AI__Service__Mitmproxy │
  │    browser ──HTTP_PROXY──┐             │      │     (FastAPI, API-key gated)   │
  │                          ▼             │      │                                │
  │  mitmproxy   :8080 (proxy)             │      │   POST /capture/sessions       │
  │    mitmweb --scripts=active.py        │      │   GET  /capture/policy         │
  │    ┌──────────────────────────────┐   │      │   POST /capture/flows  ◄───────┼── ingest
  │    │ sg_capture_interceptor.py    │───┼──────┼──▶GET  /capture/flows          │
  │    │   request(): apply policy    │   │ pull │   GET  /capture/sessions/{}/har│
  │    │   response(): ship flow      │───┼──────┼──▶GET  /capture/interceptors   │
  │    └──────────────────────────────┘   │ push │                                │
  │  :8081 mitmweb UI (container-local)   │      └────────────────────────────────┘
  └───────────────────────────────────────┘
```

- **Data plane** (this stack, EC2): the browser's bytes flow through mitmproxy.
  Only `mitmproxy` ever touches raw traffic; only `sg-playwright`'s
  `Step__Executor` touches `page.*` (CLAUDE.md rule 16).
- **Control plane** (external, durable): the MGraph service holds policy + the
  interceptor registry + the flow store. The **interceptor script is the only
  bridge** between the two — it pulls config and pushes flows over HTTPS.

This split is the whole design: the EC2 stack stays ephemeral and stateless; all
state lives in the Lambda-backed service.

## 3. The bundled interceptor script — `sg_capture_interceptor.py`

The glue. A single mitmproxy addon script, **baked into the stack** and selected
by default (this is the "interceptor script we include in it"). It is a
duck-typed addon (no mitmproxy imports at module load — mirrors
`prometheus_metrics_addon.py`), configured purely from environment.

| Hook | Behaviour |
|------|-----------|
| `load()` | Read `SG_CAPTURE__BACKEND_URL`, `SG_CAPTURE__API_KEY`, `SG_CAPTURE__SESSION_ID`. `POST /capture/sessions` (or reuse the injected id). `GET /capture/policy` → cache `Schema__Capture__Policy`. |
| `request(flow)` | Stamp `x-sg-request-id` (12-char hex) + `x-sg-request-ts` (mirrors `Default_Interceptor`). Evaluate egress policy: `ALLOW` (pass), `BLOCK` (short-circuit with 403), `REDACT` (strip matched headers/body fields), `LOG` (no-op beyond capture). |
| `response(flow)` | Build `Schema__Capture__Flow`, append to an in-memory ring buffer. |
| `done()` / timer | Flush the buffer to `POST /capture/flows` in **batches** (size + interval bound). On backend failure, spool to local NDJSON at `PATH__CAPTURE_SPOOL` and retry — capture never blocks the browser. |

Design rules it inherits from the codebase:

- **Allowlist-gated, deny-aware** — policy defaults are explicit; an empty policy
  means "log only", never "block all browsing" (would brick the stack). Egress
  *blocking* is opt-in per rule. (cf. CLAUDE.md rule 10 — `Evaluate` is deny-all;
  here the data plane must default to *pass* or the browser dies.)
- **Resilient to backend downtime** — local spool + async flush; the browser path
  is never gated on the Lambda being warm.
- **No raw secrets in flows** — `REDACT` rules run *before* a flow is buffered, so
  redacted material never leaves the EC2 host.

## 4. Schemas (Type_Safe — one class per file, no Literals, `Safe_*` primitives)

Lives under `sg_compute_specs/pw_capture/schemas/` (stack side) and is mirrored
as the wire contract the MGraph service implements (§5).

| Schema | Key fields |
|--------|-----------|
| `Schema__Capture__Session` | `session_id: Safe_Str__Id`, `created_at: Safe_Str__Text`, `stack_name`, `creator`, `ingest_token: Safe_Str__Id` |
| `Schema__Capture__Flow` | `flow_id`, `session_id`, `request_id`, `method`, `scheme`, `host`, `path`, `status_code: Safe_Int`, `bytes_request`, `bytes_response`, `elapsed_ms`, `started_at`, `egress_action: Enum__Capture__Egress__Action`, `redacted: bool` |
| `Schema__Capture__Policy` | `mode: Enum__Capture__Policy__Mode`, `allow_hosts: List__Safe_Str__Host`, `block_hosts: List__Safe_Str__Host`, `redact_headers: List__Safe_Str__Id`, `redact_json_paths: List__Safe_Str__Text` |
| `Schema__Capture__Interceptor__Choice` | `kind: Enum__Capture__Interceptor__Kind`, `name: Safe_Str__Id`, `inline_source: Safe_Str__Vnc__Interceptor__Source` (reuse the VNC primitive) |
| `Schema__Capture__Flow__Page` | `flows: List__Schema__Capture__Flow`, `next_cursor: Safe_Str__Id`, `total: Safe_Int` |

Enums (no Literals — CLAUDE.md rule 3):

| Enum | Values |
|------|--------|
| `Enum__Capture__Egress__Action` | `ALLOW`, `BLOCK`, `REDACT`, `LOG` |
| `Enum__Capture__Policy__Mode` | `OBSERVE` (capture only), `ENFORCE` (apply block/redact) |
| `Enum__Capture__Interceptor__Kind` | `NONE`, `NAME` (registry), `INLINE`, `REMOTE` (pull from MGraph registry by name+version) |

`REMOTE` is the new shape over N5: the interceptor source is **fetched from the
MGraph registry at boot**, so an interceptor can be published once and reused
across every `pw_capture` stack.

## 5. Control-plane API contract (PROPOSED additions to `MGraph-AI__Service__Mitmproxy`)

> The external repo is today a FastAPI/Lambda scaffold from the MGraph template
> (Type_Safe / OSBot-Utils, API-key auth, multi-stage CI/CD). These routes are
> **PROPOSED for that repo** and must be ratified there. They follow the same
> `Fast_API_Routes` + `add_route_*` registration pattern the template already uses.

| Method | Path | Body / query | Returns |
|--------|------|--------------|---------|
| POST | `/capture/sessions` | `{stack_name, creator}` | `Schema__Capture__Session` (+ `ingest_token`) |
| GET | `/capture/sessions/{id}` | — | `Schema__Capture__Session` |
| GET | `/capture/policy` | `?session_id=` | `Schema__Capture__Policy` |
| PUT | `/capture/policy` | `Schema__Capture__Policy` | updated policy (operator sets enforcement) |
| POST | `/capture/flows` | `{session_id, flows[]}` (batch) | `{accepted: int}` |
| GET | `/capture/flows` | `?session_id=&host=&cursor=` | `Schema__Capture__Flow__Page` |
| GET | `/capture/flows/{flow_id}` | — | `Schema__Capture__Flow` |
| GET | `/capture/sessions/{id}/har` | — | HAR 1.2 JSON (raw `Response`, not `.json()` — accepted exception) |
| GET | `/capture/interceptors` | — | list of registry entries |
| GET | `/capture/interceptors/{name}` | `?version=` | interceptor source (for `kind=REMOTE`) |
| POST | `/capture/interceptors` | `{name, version, source}` | registry entry (publish) |

All routes API-key-gated via `FAST_API__AUTH__API_KEY__{NAME,VALUE}` (the
template's existing convention). The stack authenticates with one key; the
`ingest_token` returned by `POST /capture/sessions` scopes flow-ingest to a
single session.

**Storage:** out of scope for this spec to pin, but the obvious v1 is the MGraph
service's existing persistence layer (S3-backed JSON for flows, keyed by
`session_id`). Flow batches are append-only; HAR export is a read-side
projection.

### 6.1 Compose shape

`PwCapture__Compose__Template` renders **2 containers** on one bridge network
(consistent with the post-Phase-C 2-container Playwright EC2):

| Service | Image | Ports | Notes |
|---------|-------|-------|-------|
| `sg-playwright` | `diniscruz/sgraph-ai-service-playwright` (this repo's image) | `:8000` | `SG_PLAYWRIGHT__DEFAULT_PROXY_URL=http://mitmproxy:8080`, `IGNORE_HTTPS_ERRORS=true` |
| `mitmproxy` | `mitmproxy/mitmproxy:10.4.2` (**pinned — VNC precedent**) | `:8080` proxy, `:8081` UI (network-local) | `mitmweb --scripts=/interceptors/active.py`; `/interceptors:ro` bind-mount |

The **MGraph mitmproxy service is not a container in this stack** — it is the
external backend, referenced by `SG_CAPTURE__BACKEND_URL` + `SG_CAPTURE__API_KEY`
in the mitmproxy container env.

### 6.2 Env vars consumed by the interceptor

| Var | Purpose |
|-----|---------|
| `SG_CAPTURE__BACKEND_URL` | Base URL of the MGraph mitmproxy service |
| `SG_CAPTURE__API_KEY` | API key for that service |
| `SG_CAPTURE__SESSION_ID` | Optional — reuse an existing session; else the interceptor opens one |
| `SG_CAPTURE__POLICY_MODE` | `OBSERVE` (default) / `ENFORCE` |
| `SG_CAPTURE__BATCH_SIZE` / `SG_CAPTURE__FLUSH_MS` | Ingest batching bounds |

## 7. CLI surface

The 8 standard verbs come free from `Spec__CLI__Builder`
(`v0.2.6__spec-cli-contract.md`): `list · info · create · delete · wait · health
· connect · exec`. `create` carries the `--max-hours=1` default (D2).

Extra verbs (`app.command()`):

```
sg-compute spec pw_capture create  [name?] --region --instance-type
                                    --backend-url URL --api-key KEY
                                    --interceptor NAME | --interceptor-script FILE
                                    --policy-mode observe|enforce --wait
sg-compute spec pw_capture flows    [name?] [--live] [--host H] [--limit N]
                                    # --live peeks mitmweb on the box;
                                    # default queries the MGraph backend (durable)
sg-compute spec pw_capture policy   [name?] [--set FILE] [--mode observe|enforce]
sg-compute spec pw_capture export   [name?] --har OUT.har   # pulls from backend
sg-compute spec pw_capture interceptors            # list registry + baked names
```

`--interceptor`/`--interceptor-script` map to `Schema__Capture__Interceptor__Choice`
exactly as `sp vnc` does (`NAME` baked, `INLINE` from a local file); a registry
name resolves to `kind=REMOTE`. Both-given → `typer.BadParameter` (VNC precedent).

## 8. Auth & trust

| Hop | Mechanism |
|-----|-----------|
| caller → sg-playwright | `X-API-Key` (existing) |
| browser → mitmproxy | `HTTP(S)_PROXY` env; TLS interception trusted via `IGNORE_HTTPS_ERRORS=true` (browser side) — same as the vault-app stack. (Optional hardening: mount the mitmproxy CA into the browser trust store instead.) |
| interceptor → MGraph service | `X-API-Key` (`SG_CAPTURE__API_KEY`) for setup + policy; `ingest_token` for `POST /capture/flows` |
| operator → mitmweb UI | network-local `:8081`; reach via `sg-compute spec pw_capture connect` (SSM) — **not** exposed on the SG |

Security notes (carried from the v0.2.41 reverse-proxy side-effects analysis):

- The MGraph backend now holds **captured traffic** — sensitive by definition.
  `REDACT` runs on the EC2 host *before* egress, so redacted material never
  reaches the backend.
- mitmweb's `:8081` and the mitmproxy `:8080` proxy port are **never** in the
  security group — loopback / docker-network only (cf. VNC `Vnc__SG__Helper`).

Reuse the established local proxy ladder (`tests/local/test_L{1..4}`) and add the
new control-plane layer, all via in-memory composition (CLAUDE.md testing rules):

| Layer | What it proves |

| L2 | service in-process proxy wiring |
| L3 | browser through a local HTTP proxy |

| **L5 (new)** | `sg_capture_interceptor` → MGraph backend ingest, against an **in-memory** MGraph stack composed via `register_*__in_memory()` (no mocks, no patches) — assert flow records land with correct schema, policy `BLOCK`/`REDACT` apply, spool-on-failure retries |
| deploy-via-pytest | numbered `test_1__create_stack`, `test_2__health`, `test_3__drive_browser_through_proxy`, `test_4__flows_in_backend`, `test_5__export_har`, `test_6__delete_stack` |

## 10. What is NOT in v1

| Excluded | Reason |
|----------|--------|
| WebSocket flow capture | mitmproxy captures HTTP(S); WS streaming to the backend is deferred (same cap as the v0.2.41 reverse proxy). |
| Real-time flow streaming | Batch ingest only; live tailing stays on the box via `flows --live`. |
| mitmproxy v11+ | Pinned to `10.4.2` per the VNC reverse-proxy/CSRF finding until re-verified. |
| Replacing `agent_mitmproxy` | This stack is additive. The custom sidecar + its admin API are untouched. |
| Interceptor hot-swap over SSM | `REMOTE`/`INLINE` chosen at create time; runtime swap is a fast-follow (mirrors the vault-app deferred `set-interceptor`). |
| MGraph storage backend choice | Pinned to "use the service's existing persistence"; durable-store design is owned by that repo. |

## 11. Open decisions (need owner answer before Dev starts)

1. **MGraph service maturity** — its mitmproxy-specific surface is not documented
   publicly today (template scaffold). §5 must be confirmed against its actual
   code, and the routes ratified in that repo, before the stack side can integrate.
2. **Session ownership** — does the stack open the capture session (`POST
   /capture/sessions` at interceptor `load()`), or does the CLI open it at
   `create` time and inject `SG_CAPTURE__SESSION_ID`? (Recommend: **CLI opens it**,
   so the session id is known to the operator before the box is warm.)
3. **Default policy mode** — `OBSERVE` (recommended — never bricks browsing) vs
   `ENFORCE`.
4. **CA trust hardening** — keep `IGNORE_HTTPS_ERRORS=true` (simple, matches
   vault-app) vs mount the mitmproxy CA into the browser trust store (stricter).
5. **Lives in this repo or the MGraph repo?** — the *stack spec* (`pw_capture`)
   belongs here (SG/Compute spec); the *backend routes* belong in the MGraph repo.
   This document is the cross-repo contract between them.
