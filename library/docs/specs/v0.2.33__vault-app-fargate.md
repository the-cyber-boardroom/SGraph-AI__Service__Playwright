# Spec — `sg vault-app fargate`

`sg vault-app fargate` is a Typer sub-app that manages vault container
lifecycle on AWS ECS Fargate. It provides two distinct operational modes:
**setup** (cluster-level, one-time provisioning) and **start** (task-level,
per-session fast path).

---

## Two-Mode Shape

| Mode | Frequency | Latency budget | Reversal |
|------|-----------|---------------:|---------|
| **Setup** | Once per account / region / environment | Minutes (one-time) | `setup delete` |
| **Start** | Every vault session | Target < 30 s warm path | `stop` |

Everything that can be prepared ahead of time belongs in setup. The start path
contains only: resolve config from AWS tags, run task, wait for RUNNING, resolve
ENI IP, wait for HTTP health.

---

## Full Command Tree

```
sg vault-app fargate

  setup                                      CLUSTER-LEVEL (one-time)
    check    [--cluster C] [--phase PHASE] [--json]
    status   [--cluster C] [--json]
    create   [--cluster C] [--phase PHASE] [--yes] [--time] [--json]
    update   [--cluster C] [--phase PHASE] [--yes] [--time] [--json]
    delete   [--cluster C] [--phase PHASE] [--yes] [--time] [--json]
    plan     [--cluster C] [--phase PHASE] [--json]
    show     [--cluster C]

  start    [--slug S] [--cluster C]
           [--cpu 512] [--memory 1024]
           [--with-aws-dns] [--public-ip|--no-public-ip]
           [--launch-type FARGATE_SPOT|FARGATE]
           [--seed-vault-keys K1,K2] [--access-token T]
           [--time] [--json] [--yes]

  stop     [--slug S] [--cluster C] [--yes] [--time] [--json]
  restart  [--slug S] [--cluster C] [--time] [--json]
  health   [--slug S] [--cluster C] [--timeout 30]
  url      [--slug S] [--cluster C]
  open     [--slug S] [--cluster C]
  logs     [--slug S] [--cluster C] [--since 30m] [--follow] [--source vault|ecs]
  info     [--slug S] [--cluster C]
  timings  [--slug S] [--cluster C] [--last 10] [--json]

  list     [--cluster C] [--clusters] [--json]
```

### Cluster vs slug semantics

- **Cluster** — tenancy / use-case grouping. Carries shared infrastructure
  (subnets, SG, IAM roles, log group, ECR repo). Long-lived.
- **Slug** — identifier of one running vault container (one ECS task). Lives
  only while the task runs. Multiple slugs coexist in one cluster.
- Relationship: **1 cluster : N slugs**.

When `--cluster` is omitted on task-level commands the resolver checks:
`$SG_VAULT_APP__FARGATE__CLUSTER` → sole tagged cluster → `typer.BadParameter`.

When `--slug` is omitted the resolver checks:
sole RUNNING task in cluster → `typer.BadParameter` listing candidates.

## Tag Schema (written to ECS cluster during `setup create`)

| Tag key | Example value | Purpose |
|---------|--------------|---------|
| `Stack` | `sg-vault-app-fargate` | Discovery sentinel — used by list / resolver |
| `VaultApp__Subnets` | `subnet-aaa,subnet-bbb` | Subnet IDs for RunTask |
| `VaultApp__SecurityGroup` | `sg-ccc` | Security group for RunTask |
| `VaultApp__DnsZone` | `sg-compute.sgraph.ai` | Optional; enables `--with-aws-dns` |
| `VaultApp__ExecutionRoleArn` | `arn:aws:iam::123:role/vault-app-fargate-execution` | ECS execution role |
| `VaultApp__TaskRoleArn` | `arn:aws:iam::123:role/vault-app-fargate-task` | Optional task role |
| `VaultApp__LogGroup` | `/ecs/vault-app` | CloudWatch log group |
| `VaultApp__EcrRepoName` | `sg-send-vault` | ECR repository name |
| `VaultApp__Region` | `eu-west-2` | Region where setup was run |
| `VaultApp__CreatedAt` | `2026-05-19T00:00:00Z` | Creation timestamp |

Config is read back from these tags at start time — no local config file.

## Setup Phases

Ordered by dependency. `setup create` runs forward; `setup delete` runs in
reverse.

| Phase | Wraps | What it ensures |
|-------|-------|----------------|
| `ECR` | `ECR__AWS__Client` | ECR repo `sg-send-vault` exists in account/region |
| `IAM` | `IAM__AWS__Client` | Execution role + `AmazonECSTaskExecutionRolePolicy` attached |
| `LOGS` | `Logs__AWS__Client` | CloudWatch log group, 7-day retention |
| `CLUSTER` | `Fargate__AWS__Client` | ECS cluster with `VaultApp__*` tag set |
| `IMAGE_MIRROR` | subprocess `docker pull/tag/push` | `diniscruz/sg-send-vault:latest` mirrored to ECR, pinned by SHA |
| `TASK_DEF` | `Fargate__AWS__Client` | Task definition with port mappings (8080/tcp, 443/tcp), ECR image URI pinned to SHA, execution role, log group |

Each phase can be run individually via `--phase ECR|IAM|LOGS|CLUSTER|IMAGE_MIRROR|TASK_DEF|all`.

Idempotency: every `create` is an upsert. An already-existing resource returns
status `SKIPPED` (yellow) rather than `ERROR`.

## Start Phases

The fast path — target total < 30 s on a warm setup.

| Phase | Time budget | What happens |
|-------|------------:|-------------|
| `RESOLVE_CONFIG` | < 200 ms | Two parallel describe calls: `describe_cluster` (tags) + `describe_task_definition` (latest revision) |
| `RUN_TASK` | < 1 s | `fargate_client.run_task(...)` with subnets + SG from cluster tags |
| `WAIT_RUNNING` | 3–10 s | Poll `describe_tasks` every 1 s; capped at 30 s |
| `RESOLVE_ENI` | < 500 ms | `ec2_client.describe_network_interfaces(eni_id)` — get public IP |
| `DNS_UPSERT` | 200–500 ms | Only when `--with-aws-dns` is set and cluster has `VaultApp__DnsZone` |
| `WAIT_HEALTH` | 2–15 s | HTTP poll `https://<ip>:443/info/health` (or `:8080`) with adaptive backoff |

## Mutation Gate

All mutating commands (`setup create/update/delete`, `start`, `stop`,
`restart`) require:

```
SG_VAULT_APP__FARGATE__ALLOW_MUTATIONS=1
```

`Mutation__Gate__Scope` sets this environment variable (and the underlying
`SG_AWS__FARGATE__ALLOW_MUTATIONS`, `SG_AWS__IAM__ALLOW_MUTATIONS`,
`SG_AWS__LOGS__ALLOW_MUTATIONS`) for the duration of the command only, so
users export one variable rather than five.

## AWS Resources Managed

| Resource | Created by phase | Deleted by phase |
|----------|-----------------|-----------------|
| ECR repository | ECR | ECR |
| IAM execution role | IAM | IAM |
| CloudWatch log group | LOGS | LOGS |
| ECS cluster | CLUSTER | CLUSTER |
| Task definition revision | TASK_DEF | TASK_DEF |
| ECS task (per session) | `start` | `stop` |

No VPC, subnet, or security group is created — these are passed in via
`--subnets` and `--sg` at `setup create` time and recorded as cluster tags.

## What is NOT in v1

The following were explicitly excluded from v1 to keep the start path fast
and the scope bounded:

| Feature | Reason excluded |
|---------|----------------|
| DNS upsert (Route 53) | Optional via `--with-aws-dns`; not default. No DNS wiring on hot path unless requested. |
| ALB / load balancer | Adds 60–90 s to setup; per-session Fargate task gets a direct public IP. Out of scope for v1. |
| AWS Secrets Manager | Peer SG vaults handle secrets. No Secrets Manager dependency in the vault container. |
| EFS volume mounts | Peer SG vaults handle persistence. `SEND__STORAGE_MODE=memory` is hard-coded. |
| `bake` / SOCI indexing | Future optimisation for sub-5 s cold starts. |
| `connect` / ECS exec | Requires `execute-command` enabled at cluster creation time. Deferred. |
| `extend` (auto-terminate timer) | Requires EventBridge + stop-task Lambda. Deferred. |
