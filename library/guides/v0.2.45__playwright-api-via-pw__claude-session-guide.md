# Playwright API — Guide for a Claude Web Session (v0.2.45, via `/pw`)

> **You are**: a Claude session driving the `diniscruz/sg-playwright:v0.2.45` browser-automation
> service through the **vault's `/pw` reverse proxy** on an ephemeral EC2 stack created with
> `sg va create --with-playwright --with-aws-dns --wait`. You hold no Playwright yourself —
> every browser action is an HTTP call. This guide is paste-ready: nothing else needed.

## 0. Connect

The launching operator gives you two values:

```
HOST   = https://<name>.sg-compute.sgraph.ai      # the FQDN sg va create prints (Let's Encrypt cert — trusted, no -k needed)
TOKEN  = <the access-token from `sg va info`>
```

Every call goes to `${HOST}/pw/...` with:

```
x-sgraph-access-token: ${TOKEN}
Content-Type: application/json
```

**Use `x-sgraph-access-token` exactly — do NOT use `X-API-Key`.** The proxy in front of the
service strips your header and injects `X-API-Key` server-side for the upstream Playwright.
Sending `X-API-Key` from a browser-origin caller gets rejected by the vault's CORS preflight
(`x-api-key` is not in the allow-list); sending `x-sgraph-access-token` is allowed.

If you're a sandboxed/null-origin caller (iframe with `sandbox="allow-scripts"`), this same
header works — CORS allows `*` origins for non-credentialed requests.

## 1. Smoke test (do this first)

```bash
curl -s "$HOST/pw/health/info" -H "x-sgraph-access-token: $TOKEN" | jq .service_version
# expect: "v0.2.45"  (anything starting "v0.1." = old image — tell the operator to rebuild)

curl -s -X POST "$HOST/pw/sequence/execute" \
  -H "x-sgraph-access-token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"steps":[{"action":"navigate","url":"https://example.com"},
                {"action":"wait_for","selector":"body","timeout_ms":5000},
                {"action":"screenshot","full_page":true}],
       "capture_config":{"screenshot":{"enabled":true,"sink":"inline"}}}' \
  | jq '{engine, status, steps_passed, n_artefacts:([.step_results[].artefacts|length]|add)}'
# expect: {"engine":"sync","status":"completed","steps_passed":3,"n_artefacts":1}
```

If smoke is green you are unblocked. The exact same shape (navigate + wait_for + screenshot)
crashed the v0.1.162 image with a "sync API inside asyncio loop" error — confirming you're
on v0.2.45 is the whole point of the smoke.

## 2. Endpoints (under `/pw`)

| Method | Path | What it is |
|--------|------|------------|
| GET  | `/pw/health/info`         | service identity + version (use to confirm image version) |
| GET  | `/pw/health/status`       | liveness; `healthy:false` is OK if only the `connectivity` sub-check fails (a known internal probe, not your concern) |
| GET  | `/pw/health/capabilities` | declared capabilities — **schema empty today**, a known gap (§7) |
| POST | `/pw/screenshot`          | one-shot: body `{url, full_page?, format?, click?, javascript?}` → JSON `{screenshot_b64, ...}` |
| POST | `/pw/screenshot/batch`    | batched JSON |
| POST | `/pw/sequence/execute`    | **the workhorse — multi-step declarative sequence** |
| POST | `/pw/browser/{navigate,click,fill,get-content,get-url,screenshot}` | one-shot helpers (each launches fresh Chromium for one action) |
| GET  | `/pw/openapi.json`, `/pw/docs` | Swagger + machine-readable spec (prefix-correct) |

**Use `/pw/sequence/execute` for anything beyond one action** — it's one Chromium process per
sequence (cheap), shared DOM, lower overhead than chaining `/browser/*` one-shots.

## 3. The 14 working step verbs (v0.2.45)

| Verb | Required | Optional | Notes |
|------|----------|----------|-------|
| `navigate` | `url` | `wait_until` (`load`/`domcontentloaded`/`networkidle`), `timeout_ms` | |
| `click` | `selector` | `timeout_ms`, `button`, `click_count`, `delay_ms`, `force` | |
| `fill` | `selector`, `value` | `clear_first`, `timeout_ms` | `clear_first:false` → types via `press_sequentially` |
| `press` | `key` | `selector` (omit → active element) | `key` is an enum: `Enter, Tab, Escape, Backspace, Delete, ArrowUp/Down/Left/Right, Control+a/c/v` |
| `select` | `selector`, `values` (list) | `timeout_ms` | dropdown; pass `["one"]` for single, `["a","b"]` for multi-select |
| `hover` | `selector` | `timeout_ms` | |
| `scroll` | one of: `selector` / `(x,y)` | `timeout_ms` | `selector` → scroll element into view; `x,y` → `page.mouse.wheel(x,y)` |
| `wait_for` | one of: `selector` / `url_pattern` / `state` | `timeout_ms`, `visible` (`true`=visible / `false`=attached) | bare `wait_for` → waits for `load` |
| `screenshot` | — | `full_page`, `selector`, `timeout_ms` | produces an inline-PNG artefact (see §5) |
| `get_content` | — | `selector`, `content_format` (`html`/`text`), `inline_in_response` | result has `content` + `content_type` |
| `get_url` | — | — | result has `url` |
| `evaluate` | `expression` | — | **deny-by-default allowlist** — only constant, side-effect-free reads pass (`document.title`, `window.location.href`, `window.innerWidth`). For bulk DOM use `get_content`. |
| `set_viewport` | `viewport: {width, height}` | — | |
| `dispatch_event` | `selector`, `event_type` | `event_init`, `timeout_ms` | synthetic DOM event (e.g. `click`, `input`) |

`video_start` / `video_stop` are intentionally **not** step verbs — recording is a
context-level concern routed through `capture_config.video` (not wired yet — §7).

## 4. The response — typed, stable, per-step

```json
{
  "engine": "sync",
  "sequence_id": "safe-id_xxxx",
  "trace_id": "abcd1234",
  "status": "completed",            // completed | failed | partial
  "total_duration_ms": 1834,
  "steps_total": 3, "steps_passed": 3, "steps_failed": 0, "steps_skipped": 0,
  "step_results": [
    { "step_id":"0", "step_index":0, "action":"navigate", "status":"passed",
      "duration_ms":920, "error_message":null, "error_type":null, "artefacts":[] },
    { "step_id":"1", "step_index":1, "action":"wait_for",  "status":"passed", ... },
    { "step_id":"2", "step_index":2, "action":"screenshot","status":"passed",
      "artefacts":[{"artefact_type":"screenshot","sink":"inline","size_bytes":13531,
                    "inline_b64":"<base64 PNG>","content_hash":"...","captured_at":...}] }
  ],
  "artefacts":[ /* duplicates the per-step artefacts; sequence-level captures will live here (§7) */ ],
  "timings":{"playwright_start_ms":518,"browser_launch_ms":82,"steps_ms":865,"browser_close_ms":6,"total_ms":1834}
}
```

**Per-step error model — HTTP 200, never aborts.** New in v0.2.45: ANY uncaught step
exception (selector-not-found, timeout, validation, even a future bug) becomes a per-step
`failed` result. The HTTP call returns 200 with a populated `step_results`; the bad step is
`status:"failed"` with `error_message` (free-text) **and** `error_type` (structured enum).
Non-2xx is reserved for request-level problems (bad auth → 401, malformed body → 422).

`error_type` ∈ `timeout | selector_not_found | navigation_failed | evaluate_rejected | assertion_failed | unsupported_action | unknown`. Branch on this in your retry/reporting code.

`sequence_config.halt_on_error`: `true` (default) → stop at first failure, mark rest
`skipped`; `false` → run all. `default_step_timeout_ms` sets the sequence-wide deadline.

`engine` reports which execution engine ran — always `"sync"` in v0.2.45. The async engine
(`engine:"async"`) is queued (§7).

## 5. Artefacts (today)

Each artefact in v0.2.45 is:

```json
{ "artefact_type":"screenshot",     // screenshot | page_content | ...
  "sink":"inline",                  // inline | vault | s3 | local_file
  "inline_b64":"iVBORw0K…",         // when sink=inline — actual base64 bytes
  "vault_ref":null, "s3_ref":null, "local_ref":null,
  "size_bytes":13531, "content_hash":"23090cba19", "captured_at":1780054737357 }
```

- **`inline` works** for screenshot + get_content. Default sink — use it.
- **`vault` / `s3`** are seams (return `NotImplementedError` unless wired) — don't use yet.
- **No `step_index` / `content_type` / `encoding` / `filename` fields** on the artefact
  itself — proposed in v0.2.42 but not in v0.2.45. The owning step is inferred from its
  position in `step_results[i].artefacts`.

### 6.4 Failure isolation (proves halt_on_error semantics)

```json
{"steps":[
  {"action":"navigate","url":"https://example.com"},
  {"action":"wait_for","selector":"#definitely-not-there","timeout_ms":2000},
  {"action":"get_url"}
],
 "sequence_config":{"halt_on_error":false}}
```

Expect: HTTP 200, `status:"partial"`, `step_results`:
- navigate → `passed`
- wait_for → `failed`, `error_type:"timeout"`
- get_url  → `passed` (continued because halt_on_error=false)

Swap to `halt_on_error:true` (or omit it) → `wait_for` fails, `get_url` is `skipped`.

### 6.5 Stress (concurrency)

Fire ~10 sequences in parallel; assert no cross-talk (each gets its own browser context),
no event-loop errors, all `trace_id`s unique:

```bash
for i in $(seq 1 10); do
  curl -s -X POST "$HOST/pw/sequence/execute" \
    -H "x-sgraph-access-token: $TOKEN" -H "Content-Type: application/json" \
    -d '{"steps":[{"action":"navigate","url":"https://example.com"},
                  {"action":"wait_for","selector":"body","timeout_ms":5000},
                  {"action":"screenshot"}],
         "capture_config":{"screenshot":{"enabled":true,"sink":"inline"}}}' \
    | jq -c '{i:'"$i"',engine,status,trace:.trace_id,passed:.steps_passed}' &
done; wait
```

Report any: `status != completed`, duplicate `trace_id`, non-200 HTTP, > 60 s end-to-end.

## 7. Known gaps — PROBE THESE EXPLICITLY

These are the deliberately-acknowledged gaps in v0.2.45. Your real-world driving WILL hit
them; treat each as a **find-and-report** task, not a blocker:

| # | Gap | What to try | What "found" looks like |
|---|-----|-------------|-------------------------|
| G1 | **Terminal screenshot from `capture_config.screenshot.enabled` without a `screenshot` step** | `{"steps":[{"action":"navigate","url":"https://example.com"}],"capture_config":{"screenshot":{"enabled":true,"sink":"inline"}}}` | Today: response has `artefacts:[]`. Target (proposed): one artefact with no owning step. |
| G2 | **`screenshot_on_fail`** | Set `capture_config.screenshot_on_fail.enabled=true`, run a sequence that ends `failed` | Today: no on-fail artefact. Target: one terminal artefact on failure only. |
| G3 | **`video`, `har`, `trace`, `console_log`, `network_log`** in `capture_config` | Set any to `enabled:true` | Today: schema-only — no artefact returned. |
| G4 | **`page_content` (terminal DOM)** in `capture_config` | Same as G3 | Today: no terminal DOM artefact. |
| G5 | **`vault` / `s3` sinks** | Set any `sink:"vault"` | Today: 5xx with `NotImplementedError`. |
| G6 | **`/pw/health/capabilities` schema** | `GET /pw/health/capabilities` and `GET /pw/openapi.json` | Today: returns a Schema but the OpenAPI definition is `{}` (empty). |
| G7 | **Async engine** (`engine:"async"`) | `POST /pw/sequence/execute-async` (route not yet added) | Today: 404. Target: parallel async route returning identical schema with `engine:"async"`. |
| G8 | **Native assertions** (`expect_selector_visible`, `expect_title_contains`, `expect_url_matches`, `expect_text`, `expect_status`) | Use any `expect_*` as a step action | Today: `error_type:"unsupported_action"` per-step. |
| G9 | **Retries / per-step timing breakdown / network control / SSE streaming / idempotency** | — | Documented as not-built; report if you'd hit a wall without them. |
| G10 | **Live screencast / CDP remote control** | — | Spike pending; not in v0.2.45. |

**Inline-bytes size cap**: there is one (real pages get big). If you ever see an artefact
truncated or a sequence response > a few MB, report exact sizes — the cap is undocumented.

Beyond this list, **anything that surprises you is a gap to report** — even "the error
message wasn't helpful" or "the OpenAPI says X but the server does Y".

## 9. Hard rules (do not violate)

- **One token per session.** It's the vault access token; treat it as a single secret.
- **No retries on a 401/422** (request-level — fix the request, not retry).
- **Per-step `failed` is normal**, not an error to retry blindly. Branch on `error_type`.
- **`evaluate` is allowlisted** — don't try to bypass with `eval` / `Function` / template
  strings; they get explicit-rejected. Use `get_content` for bulk DOM.
- **No browser state crosses requests.** Every sequence is a fresh Chromium + context;
  cookies / storage / sessions do not survive. If you need auth for the target page, pass
  it via the request's `credentials` field per call (service never retains it).
- **`/pw` is same-origin via the vault** — same browser-origin rules apply if you embed
  your code in the vault page (`x-sgraph-access-token` works in both cases).

## 10. Discovery — when this guide is wrong or incomplete

Two live sources of truth, in this order:

1. `GET ${HOST}/pw/openapi.json` — machine-readable spec from the running image. Authoritative for paths + response shapes; **may be sparse on the request body's step-shape** (the `steps` array accepts any dict — see §3 for the canonical verb list).
2. `GET ${HOST}/pw/docs` — Swagger UI of the same.

If `service_version` (from `/health/info`) ≠ `v0.2.45`, this guide may not apply — flag it.
