# Playwright API — Guide for a Claude Web Session (v0.2.54, via `/pw`)

> **You are**: a Claude session driving the `diniscruz/sg-playwright:v0.2.54` browser-automation
> service through the vault's `/pw` reverse proxy on an ephemeral EC2 stack created with
> `sg va create --with-playwright --with-aws-dns --wait`. You hold no Playwright yourself —
> every browser action is an HTTP call. This guide is paste-ready: nothing else needed.

## 0. Connect

```
HOST   = https://<name>.sg-compute.sgraph.ai      # FQDN; trusted cert; no -k
TOKEN  = <token from `sg va info`>
```

**Auth header on the `/pw` proxy is `x-sgraph-access-token`, not `X-API-Key`.** This is
the #1 first-attempt failure. The `/pw` proxy strips the inbound header and injects
`X-API-Key` upstream — so a caller sending `X-API-Key` against the proxy gets 401 at
the proxy. Only direct service access (local Docker / direct EC2 port) uses `X-API-Key`.

Every call via the `/pw` proxy (the production path):

```bash
curl -s -H "x-sgraph-access-token: ${TOKEN}" -H "Content-Type: application/json" \
     -X POST "${HOST}/pw/<route>" -d '{...}'
```

For direct (non-proxy) access, drop the `/pw` prefix AND use `X-API-Key`:

```bash
curl -s -H "x-sgraph-access-token: ${TOKEN}" "${HOST}/<route>" -d '{...}'
```

## 1. Smoke test (do this first)

```bash
curl -sf -H "x-sgraph-access-token: ${TOKEN}" "${HOST}/pw/health/info" | jq -r .service_version
# expect: "v0.2.54" or later. v0.1.* = stale image — tell the operator to rebuild.

curl -sf -H "x-sgraph-access-token: ${TOKEN}" -H "Content-Type: application/json" \
     -X POST "${HOST}/pw/sequence/execute" -d '{
  "capture_config": {"screenshot": {"enabled": true, "sink": "inline"}},
  "sequence_config": {},
  "steps": [{"action":"navigate","url":"https://example.com"},
            {"action":"get_url"},
            {"action":"screenshot","full_page":true}]
}' | jq '{status, steps_passed, n_artefacts: (.artefacts|length)}'
# expect: {"status":"completed","steps_passed":3,"n_artefacts":1}
```

## 2. Endpoint surface (under `/pw`)

| Route | Purpose |
|---|---|
| `GET /health/{info,status,capabilities}` | service version + capabilities |
| `POST /sequence/execute` | linear multi-step pipeline |
| `POST /browser/{navigate,click,fill,get-content,get-url,screenshot}` | one-shot endpoints |
| `POST /screenshot`, `POST /screenshot/batch` | simple PNG/HTML capture with `allow_all` JS allowlist |
| **`POST /inspect`** | **NEW** — probe-batch (snapshot once, probe many) |
| **`POST /session/open`** | **NEW** — open stateful session, returns `session_id` + `expires_in_ms` |
| **`POST /session/{id}/act`** | **NEW** — sequence-shape body, runs against held page |
| **`POST /session/{id}/probe`** | **NEW** — inspect-shape body (no navigate), runs against held page |
| **`POST /session/{id}/close`** | **NEW** — explicit close (also auto on TTL) |
| `GET /metrics` | Prometheus text exposition |
| `GET /docs` | Swagger UI (live against your stack) |

## 3. The 24 step verbs (v0.2.54)

| Verb | What it does | Notes |
|---|---|---|
| `navigate` | `page.goto(url, wait_until=…)` | |
| `click`, `fill`, `press`, `select`, `hover`, `scroll` | direct interactions | |
| `set_viewport`, `dispatch_event` | direct interactions | |
| `wait` | fixed-duration `page.wait_for_timeout(ms)` | **NEW (Φ2)** — explicit, intentional pause |
| `wait_for` | rich predicate — see §3.1 | |
| `screenshot` | PNG; optional `selector`, `full_page`, `viewport`, `frame_selector` | **`viewport` + artefact `width`/`height`** are new in Φ2 |
| `evaluate` | run JS — **allowlist-gated** | `return_value` + `return_type` populated (Φ1 FR-5a) |
| `get_content` | HTML/text of page or selector | |
| `get_url` | current `page.url` | |
| `get_text` | innerText of page or selector | **NEW (Φ3)**. ⚠ Light-DOM only — does NOT pierce shadow roots. For shadow-DOM-heavy apps use `get_dom_tree` (which DOES pierce open shadow roots + marks the boundary) or `screenshot`. |
| `get_html` | outerHTML of page or selector | **NEW (Φ3)** — distinct from `get_content`'s innerHTML |
| `get_dom_tree` | compact JSON tree (tag/id/class/role/rect/visible/children) — bounded by `max_depth` + `root_selector` + `include_invisible`. Walks open shadow roots + same-origin iframes (boundary marked `shadow_root:true` / `iframe:true` / `cross_origin:true`) | **NEW (Φ3 + Φ6a)** |
| `get_a11y_tree` | accessibility tree via CDP `Accessibility.getFullAXTree` — returns `{nodes: [{nodeId, role, name, ignored, childIds, …}]}`. `interesting_only` filters `ignored:true` nodes. | **NEW (Φ3)** — CDP shape (NOT the old nested tree; Playwright 1.49+ removed `page.accessibility`) |
| `get_pdf` | `page.pdf(format/landscape/print_background)` → PDF artefact via `capture_config.pdf` | **NEW (Φ3)** |
| `get_console_tail` | last N events from the page listener buffer | **NEW (Φ4)** |
| `get_network_failures` | buffered `page.on('requestfailed')` events | **NEW (Φ4)** |
| `video_start`, `video_stop` | session recording | unchanged |

### 3.1 `wait_for` predicates (precedence — top wins)

```jsonc
// in precedence order
{"action":"wait_for", "function":      "() => window.X === 1"}       // FR-1c, allowlist-gated
{"action":"wait_for", "network_idle_ms": 500, "timeout_ms": 15000}   // FR-1d — websocket+eventsource excluded from in-flight
{"action":"wait_for", "text":         "Welcome", "selector": "#main"} // FR-1a, optional scoping
{"action":"wait_for", "selector":     ".spinner", "selector_gone": true} // FR-1b
{"action":"wait_for", "selector":     "#login"}                       // visible (default) / +"visible": false → attached
{"action":"wait_for", "url_pattern":  "https://x.example/dashboard*"}
{"action":"wait_for", "state":        "networkidle"}                  // load | domcontentloaded | networkidle
```

## 4. `/inspect` — the headline new feature (Φ5)

Snapshot once, probe many. Replaces the "call `/sequence/execute` 5 times to look at the same page from 5 angles" pattern.

```bash
curl -s -H "x-sgraph-access-token: ${TOKEN}" -H "Content-Type: application/json" \
     -X POST "${HOST}/pw/inspect" -d '{
  "navigate": {"url": "https://app.example.com"},
  "settle":   [{"action": "wait_for", "text": "Welcome back", "timeout_ms": 10000}],
  "probes": {
    "current_url": {"action": "get_url"},
    "page_dom":    {"action": "get_dom_tree", "max_depth": 4},
    "a11y":        {"action": "get_a11y_tree", "interesting_only": false},
    "main_text":   {"action": "get_text", "selector": "main"},
    "shot":        {"action": "screenshot", "full_page": false}
  },
  "diagnostics_on_fail": true
}' | jq '{status, probe_keys: (.probe_results|keys), has_diagnostics: (.diagnostics != null)}'
```

Response shape:
```json
{
  "inspect_id": "safe-id_...",
  "trace_id":   "...",
  "status":     "completed" | "partial" | "failed",
  "navigate_result": {Step__Result},
  "settle_results":  [{Step__Result}, ...],
  "probe_results":   {"current_url": {...}, "page_dom": {...}, ...},   // keyed by your probe names
  "diagnostics":     {"console_log": [...], "network_failures": [...]} | null,
  "artefacts": [...],
  "timings":   {...}
}
```

Rules:
* Probes are **read-only**. Including `click` / `fill` / `navigate` / `evaluate` / `wait_for` in `probes` → HTTP 422.
* `diagnostics_on_fail=true` (default): if ANY step fails, response carries `diagnostics: {console_log, network_failures}`. On green, `diagnostics` is `null`. Cheap insurance.
* **`screenshot` and `get_pdf` probes need `capture_config` at the top level** of the inspect body — otherwise the step reports `passed` but `artefacts: []`. The capture-config sink is what writes the bytes anywhere; without it the bytes are captured but go nowhere.

```jsonc
// example: /inspect with a screenshot probe that ACTUALLY emits an artefact
{
  "navigate": {"url": "https://example.com"},
  "settle":   [],
  "probes":   {"shot": {"action": "screenshot", "full_page": false}},
  "capture_config": {"screenshot": {"enabled": true, "sink": "inline"}}   // ← REQUIRED for the shot to land in artefacts[]
}
```

## 5. `/session/*` — opt-in stateful (Φ7)

When you need multiple acts/probes against the SAME page (e.g. one decrypt + many reads).

```bash
# Open
SID=$(curl -s -H "x-sgraph-access-token: ${TOKEN}" -H "Content-Type: application/json" \
      -X POST "${HOST}/pw/session/open" -d '{"ttl_ms": 300000}' | jq -r .session_id)

# Act — navigate + decrypt the held page
curl -s -H "x-sgraph-access-token: ${TOKEN}" -H "Content-Type: application/json" \
     -X POST "${HOST}/pw/session/${SID}/act" -d '{
  "steps": [
    {"action": "navigate", "url": "https://dev.vault.sgraph.ai/#tcss7to5vfp6asjbm1t1p5ng:rqw3wk4b"},
    {"action": "wait_for", "text": "Unlocked"}
  ]
}' | jq .status

# Probe — many reads against the held page (no re-navigation)
curl -s -H "x-sgraph-access-token: ${TOKEN}" -H "Content-Type: application/json" \
     -X POST "${HOST}/pw/session/${SID}/probe" -d '{
  "settle": [],
  "probes": {"vault_url": {"action": "get_url"},
             "vault_dom": {"action": "get_dom_tree", "max_depth": 3}}
}' | jq '.probe_results | keys'

# Close
curl -s -H "x-sgraph-access-token: ${TOKEN}" -X POST "${HOST}/pw/session/${SID}/close" | jq
```

Lifecycle notes:
* `ttl_ms` is capped at `capabilities.max_session_lifetime_ms`.
* Each `/act` or `/probe` call refreshes the TTL (sliding window).
* TTL expiry is lazy — cleanup happens on the next request to ANY endpoint, including `/health/info` and `/metrics`. No background sweep thread; if the deployment is polled, sessions are reaped.
* Unknown / expired session → HTTP 404.
* Each session owns a dedicated worker thread. Playwright sync API is thread-affine; the worker thread owns the runtime + browser + page for the session's whole lifetime. You never see this from the wire — it's internal — but it explains why `/session/*` is reliable now.

## 6. Step-result shape (every endpoint)

Every step result is `Schema__Step__Result__Base` with verb-specific fields lifted onto it. Most are `null`; check the field that matches your verb.

```json
{
  "step_id": "0", "step_index": 0,
  "action": "navigate", "status": "passed",
  "duration_ms": 800,
  "artefacts": [],
  "error_message": null, "error_type": null,

  // verb-specific (most null per step)
  "content": null, "content_format": null, "content_type": null,
  "url":                "https://...",                  // get_url
  "text":               null,                           // get_text
  "html":               null,                           // get_html / get_content
  "dom_tree":           null,                           // get_dom_tree (nested)
  "accessibility_tree": null,                           // get_a11y_tree (flat CDP nodes)
  "return_value":       null, "return_type": null,      // evaluate
  "console_log":        null, "network_failures": null  // listener-buffer verbs
}
```

`status` is one of `passed` / `failed` / `skipped` / `pending` / `running`.
`error_type` is one of `TIMEOUT` / `NAVIGATION_FAILED` / `SELECTOR_NOT_FOUND` / `EVALUATE_REJECTED` / `UNSUPPORTED_ACTION` / `UNKNOWN`.

## 7. Capture config + artefacts

`capture_config` (per-request) wires sinks per artefact type:

```json
{
  "screenshot":         {"enabled": true,  "sink": "inline"},
  "screenshot_on_fail": {"enabled": false, "sink": "inline"},
  "video":              {"enabled": false, "sink": "inline"},
  "pdf":                {"enabled": true,  "sink": "inline"},
  "har":                {"enabled": false, "sink": "inline"},
  "trace":              {"enabled": false, "sink": "inline"},
  "console_log":        {"enabled": false, "sink": "inline"},
  "network_log":        {"enabled": false, "sink": "inline"},
  "page_content":       {"enabled": false, "sink": "inline"}
}
```

Sinks supported today: `INLINE` (base64 in response — 20 MB cap), `LOCAL_FILE` (disk inside container). `VAULT` / `S3` are scaffolded but not wired yet (Φ6b).

Artefact refs include `width` + `height` (px) for screenshots — parsed from the PNG IHDR header (Φ2 FR-7).

`console_log` / `network_log` artefacts are emitted at **sequence end** when their sink is enabled — useful for post-mortem on long sequences.

## 8. Failure handling — what to expect

Different layers behave differently:

| Layer | On failure |
|---|---|
| **HTTP** | 200 + body even for sequence failure. 4xx only for malformed request, missing/wrong API key, or unknown session. |
| **Sequence** | `status: "partial"` (some passed, some failed, no `halt_on_error`) or `"failed"` (halt + at least one failure). `step_results[i].error_message` + `error_type` carry the detail. |
| **Validation rejection** (e.g. `wait_for: function` blocked by allowlist, mutating verb in `/inspect` probes) | For `/sequence/execute` + `/session/act`: surfaces as a per-step `failed` with error_message containing the rejection. For `/inspect` probes: HTTP 422 with `detail`. |
| **Service crash mid-request** (rare, latent bug — see §10) | `httpx.RemoteProtocolError: Server disconnected without sending a response`. Container needs to restart. |

### 9.2 Render a PDF of a page

```json
{"capture_config": {"pdf": {"enabled": true, "sink": "inline"}},
 "sequence_config": {},
 "steps": [{"action":"navigate","url":"https://example.com"},
           {"action":"get_pdf","format":"A4","print_background":true}]}
```

`artefacts[0].inline_b64` is the base64 PDF.

### 9.3 Run JS that DOES return (use `/screenshot` — bypasses allowlist)


## 10. Known issues / latent bugs (probe these explicitly)

| | What | Workaround |
|---|---|---|
| Doc trap | `/inspect`'s `screenshot` / `get_pdf` probes emit `artefacts: []` when the request body has no top-level `capture_config`. The probe reports `passed` — silently. | Always set `capture_config.screenshot.enabled=true` (or `.pdf.enabled=true`) at the top of the `/inspect` body. See §4 for the exact shape. |
| Light-DOM only | `get_text` returns `""` on apps where the content is inside shadow roots — innerText of the host element doesn't pick up the shadow tree. | Use `get_dom_tree` (pierces open shadow roots, marks the boundary) or `screenshot` for shadow-heavy apps. Fixing this in the verb itself is a known fast-follow. |
| Latent | `page.locator('<missing>').screenshot(timeout=N)` may crash the service mid-response. Surfaced as `RemoteProtocolError`. Same class as `/browser/fill` against a non-existent input field. Two live tests have been intentionally dropped due to this — see `team/roles/architect/reviews/05/30/playwright-debrief-response/02__implementation-debrief.md` §2. | Don't target selectors that you're not confident exist. Always pair `screenshot`/`fill` with a preceding `wait_for: selector`. |
| Brittle | `wait_for: network_idle_ms` against analytics-heavy SPAs may never reach quiet. Buffer excludes `websocket`/`eventsource` from the in-flight count, but long-polling XHR + analytics beacons still count. | Use `wait_for: text` or `wait_for: function` against a specific signal. |
| By design | `/session/*` is single-instance — no cross-replica sharing. Lambda containers can sleep + lose sessions. | Use `/inspect` for Lambda; `/session/*` for EC2 only. |

## 11. Hard rules (do not violate)

* **Never** retry a step that returned `error_type: EVALUATE_REJECTED` — the allowlist is operator-enforced, retries won't help.
* **Never** assume the URL after `navigate` matches the URL you submitted — sites redirect. Always use `get_url` or `result.url` to read the real URL.
* **Always** parse `step_results` defensively — verb-specific fields are `null` on every step EXCEPT the one that produced them. Look at the `action` field first, then the matching field.
* **Always** send the API key as `X-API-Key` — `Authorization` headers are ignored.
* **Never** put `evaluate` in `/inspect` probes — it's a mutator (can run side-effecting JS) and is rejected with 422.
