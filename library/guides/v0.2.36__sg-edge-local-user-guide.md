# SG/Edge — `sg edge local` user guide

> **Scope.** This guide covers the **local** SG/Edge deployment only — the
> in-process, file-backed edge you bring up with `sg edge local setup`. It needs
> no AWS, no docker, and no network. It replicates the Phase-1 end-to-end flow
> (wildcard → proxy fleet → slug routing → welcome page) so you can drive and
> inspect the platform from a user / use-case point of view. Live-AWS provisioning
> (`sg edge setup *`, EC2 launch/terminate) is a separate, not-yet-built surface.

---

## 1. What the local edge is

The real SG/Edge tier is **CloudFront + wildcard ACM → an OpenResty proxy fleet →
vault targets**, coordinated by two wakers with all state in DNS. The local edge
is a faithful, pure-Python stand-in for that tier:

| Real (AWS) | Local equivalent |
|---|---|
| Route 53 zone `*.edge.sg-labs.app` | file-backed DNS at `<state_dir>/dns.json` for `edge.sg-labs.local` |
| CloudFront wildcard `*.<parent>` | `*.edge.sg-labs.local` A → `127.0.0.1` |
| OpenResty proxy fleet (EC2) | `Local__Edge__Proxy` — Python request logic + an optional real HTTP server |
| Edge Waker (writes `proxies`/`_state`) | `Local__Edge__Stack.setup()` |
| Vault Waker (writes `<slug>` A + `_sg.<slug>` TXT) | `Local__Edge__Stack.register()` |

Because the local DNS file speaks the same record shapes, the **exact same**
`SG_Edge__DNS__Helper` and reconciler logic run unchanged against it.

---

## 2. Mental model — the two records and three outcomes

Every slug is described by **two DNS records**, written by (in production) two
different wakers:

```
  <slug>.edge.sg-labs.local        A    → registration ("this slug is known")     [Vault Waker]
  _sg.<slug>.edge.sg-labs.local    TXT  → backend       ("v=1;ip=…;port=…;…")      [Vault Waker]
```

When a request arrives for `<slug>.edge.sg-labs.local`, the proxy decides based on
which records exist — the same A?/TXT? decision tree the Phase-2 OpenResty Lua hot
path uses:

| A record | TXT record | Outcome | HTTP | Page |
|:---:|:---:|---|:---:|---|
| ✓ | ✓ | **welcome** | 200 | `Welcome to the <slug> vault` |
| ✓ | ✗ | **dormant** | 503 | `… vault is waking up` (loading page; Vault Waker would fire) |
| ✗ | – | **not-recognised** | 404 | `slug not recognised` |

`setup` additionally writes the fleet-level records the Edge Waker owns:
`proxies.<parent>` A (the fleet IPs) and `_state.<parent>` TXT (the idle-teardown
counter).

---

## 3. Prerequisites

- The local stack itself is **pure Python** (3.11+). It needs `typer` + `rich`
  (already required by the `sg` CLI).
- No AWS credentials, no docker, no network are used by `sg edge local`.
- State lives under `~/.sg/edge_local/` by default; override with
  `$SG_EDGE__LOCAL_STATE_DIR` (CI and tests point this at a temp dir).

All commands are under `sg edge local` (alias `sg ed local`).

---

## 4. Quickstart — the golden path

```bash
sg edge local setup                      # bring the edge up
sg edge local register alice             # register a slug (A + backend TXT)
sg edge local request alice              # simulate a user request end-to-end
sg edge local check                      # inspect what's deployed + deviations
sg edge local teardown --yes             # destroy it
```

What `setup` then `register alice` then `request alice` looks like:

```
>>> sg edge local setup
  ✓  local edge deployed  parent=edge.sg-labs.local
     wildcard *.edge.sg-labs.local → 127.0.0.1  |  proxies: 1
     next: sg edge local register <slug>  →  sg edge local request <slug>

>>> sg edge local register alice
  ✓  registered alice  (alice.edge.sg-labs.local)
     A=True  TXT=True  backend=127.0.0.1:8080

>>> sg edge local request alice
  ✓  alice.edge.sg-labs.local  →  HTTP 200  (welcome)
     Welcome to the alice vault
     backend: 127.0.0.1:8080
```

## 5. Command reference

Every command accepts `--parent / -p` (defaults to `edge.sg-labs.local`). Read
commands accept `--json` for scripting.

### `setup`
Bring the edge up: create the local zone, write the `*.<parent>` wildcard, add one
proxy to the fleet (`proxies.<parent>`), and zero the `_state` counter. Idempotent
— running it twice leaves exactly one proxy.

### `register <slug>` `[--no-backend]`
Register a slug — writes the `<slug>.<parent>` A record (registration) and, unless
`--no-backend` is given, the `_sg.<slug>.<parent>` TXT (backend, built with
`SG_Edge__TXT__Builder`). `--no-backend` produces a **dormant** slug (A only).

```
>>> sg edge local register bob --no-backend
  ✓  registered bob  (bob.edge.sg-labs.local)
     A=True  TXT=False  backend=(none — dormant)
```

### `unregister <slug>`
Remove both records for a slug. Exits non-zero if the slug wasn't registered.

### `request <slug>` `[--body] [--json]`
Simulate one user request end-to-end, in-process (no server needed). Prints the
outcome (welcome / dormant / not-recognised), HTTP status, and backend. `--body`
prints the full HTML page; `--json` emits the structured response.

```
>>> sg edge local request ghost
  ✗  ghost.edge.sg-labs.local  →  HTTP 404  (not_recognised)
     slug not recognised: ghost
```

### `list` `[--json]`
List registered slugs and their state (`welcome` / `dormant` / `orphan-backend`).

### `status` `[--json]`
One-line snapshot: deployed?, zone, wildcard, proxy count, slug count, zero_streak.

### `check` `[--json]`
The diagnostic centrepiece — see §7. Exits non-zero if any **error**-severity
deviation is found.

### `serve` `[--port N]`
Run the local proxy as a **real HTTP server** routing by `Host` header — see §8.

### `teardown` `[--yes]`
Delete the local DNS file and stack marker. `--yes` skips the confirmation.

### `usecases` and `usecase <id|all>` `[--json]`
List and run the scripted end-to-end use-cases — see §6.

## 6. Use-cases — driving the platform one scenario at a time

The use-cases are scripted, self-contained end-to-end flows. Each runs in its
**own isolated temp state dir**, so running a use-case never touches the edge you
set up with `sg edge local setup`.

```
>>> sg edge local usecases
  UC-01  fresh-setup            Bring the edge up from scratch and confirm it is deployed.
  UC-02  register-and-welcome   Register a slug and confirm the welcome page is served end-to-end.
  UC-03  unknown-slug           Request an unregistered slug and confirm the 404 page.
  UC-04  dormant-slug           Register a slug with no backend and confirm the dormant/loading page.
  UC-05  unregister             Register, serve, unregister, and confirm the slug stops resolving.
  UC-06  check-clean            A freshly set-up edge with one slug reports no deviations.
```

Run one, or all:

```
>>> sg edge local usecase UC-02
  PASS  UC-02  register-and-welcome
      ✓  request returns 200  status=200
      ✓  kind is WELCOME  kind=welcome
      ✓  serves the slug welcome page  Welcome to the alice vault
      ✓  backend resolved  backend=127.0.0.1:8080

  1/1 use-case(s) passed

>>> sg edge local usecase all          # runs UC-01 … UC-06, prints "6/6 use-case(s) passed"
```

`usecase all --json` emits an array of results; the command exits non-zero if any
use-case fails — drop it into CI as a fast, no-AWS regression gate.

## 7. Reading `check` — the diagnostic centrepiece

`check` is the key command: it tells you exactly what is deployed/enabled and flags
any deviation. It draws a layered box diagram (browser → wildcard → proxy fleet →
slugs) and a Checks panel.

```
>>> sg edge local check
  ┌────────────────────────────────────────────────────────────────┐
  │ SG/Edge — local deployment   (edge.sg-labs.local)
  ├────────────────────────────────────────────────────────────────┤
  │ Browser
  │   │  http://<slug>.edge.sg-labs.local
  │   ▼
  │ ✓ Wildcard   *.edge.sg-labs.local  (CloudFront equiv)
  │   │
  │   ▼
  │ ✓ Proxy fleet  proxies.edge.sg-labs.local  (1 IP)
  │       • 127.0.0.1
  │   │
  │   ▼
  │ ✓ Slugs  (2 registered)
  │       ✓ alice          A+TXT  → 127.0.0.1:8080  (welcome)
  │       ● bob            A only → (dormant — Vault Waker on first hit)
  └────────────────────────────────────────────────────────────────┘
  ┌────────────────────────────────────────────────────────────────┐
  │ Checks
  ├────────────────────────────────────────────────────────────────┤
  │ · slug:bob  registered but dormant (no backend) — first request triggers the Vault Waker.
  └────────────────────────────────────────────────────────────────┘
```

Per-layer markers: `✓` healthy, `●` dormant/partial, `✗` broken. The Checks panel
lists findings by severity:

| Severity | Icon | Meaning | Examples |
|---|:---:|---|---|
| `ok` | ✓ | nothing wrong | "all checks passed" |
| `info` | · | expected non-error state | slug registered but dormant |
| `warn` | ⚠ | deviation worth fixing | orphan backend (TXT but no A); DNS records but no stack marker |
| `error` | ✗ | broken — `check` exits non-zero | missing wildcard; empty proxy fleet; zone missing |

Use `check --json` to assert on `deployed`, `wildcard`, `proxy_ips`, `slugs`, and
`issues` from a script.

## 8. Serving over real HTTP (curl / browser)

`request` is in-process. To hit the edge over a real socket — e.g. from `curl` or a
browser — run the proxy as an HTTP server that routes by `Host` header:

```bash
sg edge local serve --port 8410         # foreground; Ctrl-C to stop
```

From another shell, the easy path is `curl` with an explicit `Host`:

```bash
curl -H "Host: alice.edge.sg-labs.local" http://127.0.0.1:8410/
# → <h1>Welcome to the alice vault</h1> …
```

For a **browser**, point `*.edge.sg-labs.local` at `127.0.0.1` so the hostname
resolves. Either add explicit `/etc/hosts` lines per slug:

```
127.0.0.1   alice.edge.sg-labs.local
127.0.0.1   bob.edge.sg-labs.local
```

…or run a wildcard local resolver (e.g. `dnsmasq` with
`address=/edge.sg-labs.local/127.0.0.1`). Then browse to
`http://alice.edge.sg-labs.local:8410/` (the port matters unless you run `serve`
on port 80, which needs elevated privileges).

## 9. State, isolation, and CI

- **State files.** `<state_dir>/dns.json` (the local DNS registry) and
  `<state_dir>/stack.json` (the deployed marker). `state_dir` defaults to
  `~/.sg/edge_local`; set `$SG_EDGE__LOCAL_STATE_DIR` to relocate it.
- **Cross-process.** State is on disk, so each `sg edge local …` invocation is a
  separate process reading the same DNS file — register in one shell, request in
  another.
- **CI.** Point `$SG_EDGE__LOCAL_STATE_DIR` at a temp dir and run
  `sg edge local usecase all` (exits non-zero on any failure). It's fast and uses
  no AWS — ideal for a per-PR regression gate.

---

## 10. What is simulated vs real (honesty box)

The local edge proves the **logic and the flow**, not AWS timing behaviour:

- **Real:** the A/TXT record lifecycle, the routing decision tree, the welcome /
  dormant / not-recognised outcomes, the wildcard/fleet/slug check logic, the
  `SG_Edge__DNS__Helper` and reconciler code paths.
- **Simulated / not covered:** CloudFront DNS-cache refresh, Route 53 global
  propagation, EC2 boot variance, Lambda cold-start, real TLS termination, real
  rate limiting. Those are the AWS-specific timing scenarios that need the live
  bench environment (see brief 05 and the implementation plan).

The hard-coded AWS edge zone — `edge.sg-labs.app` — is the create/destroy-at-will
distribution the live `sg edge` commands default to; the local zone is
`edge.sg-labs.local`. Both are defined in
`sg_compute_specs/sg_edge/local/sg_edge_local__config.py`.

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `request` returns `not_recognised` for a slug you registered | wrong/empty `--parent`, or the slug was registered against a different `--parent` | match `--parent` (default `edge.sg-labs.local`); check `sg edge local list` |
| `check` says **not deployed** but `list` shows slugs | records were written (e.g. `register`) before `setup`, so there's no stack marker | run `sg edge local setup`, or `teardown --yes` to clean up |
| `check` flags **orphan backend** (warn) | a `_sg.<slug>` TXT exists with no matching `<slug>` A | re-`register <slug>` or `unregister <slug>` |
| `check` exits non-zero | an **error** finding (missing wildcard / empty fleet / missing zone) | re-run `sg edge local setup` |
| browser can't resolve `*.edge.sg-labs.local` | no local DNS mapping | add `/etc/hosts` lines or a dnsmasq wildcard (see §8); or use `curl -H "Host: …"` |
| state "leaked" between runs | a stale `$SG_EDGE__LOCAL_STATE_DIR` / `~/.sg/edge_local` | `sg edge local teardown --yes` |
