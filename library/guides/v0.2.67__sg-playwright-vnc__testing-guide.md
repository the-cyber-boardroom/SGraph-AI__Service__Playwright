# Testing sg-playwright-vnc and the `/browser` fleet

Work through the stages in order — each proves a layer the next one depends on.
Stages 1–3 need only docker on your laptop; stage 4 needs the image published;
stage 5 spends EC2 money.

## Stage 0 — one-time prerequisites

```bash
# 1. Docker Hub repo (first publish will fail without it):
#    create `sg-playwright-vnc` under the diniscruz namespace (same token).

# 2. Pull the branch and confirm the suites are green locally:
git checkout claude/trusting-franklin-fza33n && git pull
python -m pytest sg_compute_specs/content_proxy/tests/ tests/unit -q     # expect ~800+ passed
```

## Stage 1 — build the image locally and prove the desktop

```bash
docker build -f sg_compute_specs/playwright/vnc/Dockerfile \
             -t diniscruz/sg-playwright-vnc:local .

docker run -d --name pw-vnc -p 8000:8000 -p 6080:6080 --shm-size=2g \
  -e FAST_API__AUTH__API_KEY__VALUE=local-key \
  diniscruz/sg-playwright-vnc:local

# a) API tier unaffected by the desktop layer:
curl -sf -H 'X-API-Key: local-key' http://localhost:8000/health/status && echo OK

# b) noVNC serves:
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:6080/vnc.html   # → 200

# c) all five programs supervised:
docker exec pw-vnc supervisorctl status    # xvfb/openbox/x11vnc/novnc/fastapi RUNNING

# d) THE moment: open a headed browser and watch it.
#    Open http://localhost:6080/vnc.html → Connect, then:
curl -s -X POST http://localhost:8000/desktop/browser \
  -H 'content-type: application/json' -H 'X-API-Key: local-key' \
  -d '{"engine": "chromium", "start_url": "https://example.com"}'
#    → a maximised Chromium appears in the noVNC tab. The returned session_id
#      works with every /session/{id}/* endpoint — drive the SAME browser via
#      the API while you watch it.
```

Pass = all four. Repeat (d) with `"engine": "firefox"` for the second engine.

## Stage 2 — the sub-path proof (the thing that killed jlesage)

```bash
docker compose -f sg_compute_specs/playwright/vnc/spike/docker-compose.yml up -d
# open  https://localhost/browser/1/   (accept the internal-CA warning)
```

Pass = the noVNC desktop **connects and streams** behind the path-stripping
proxy — assets load AND the websocket survives. This is the exact edge shape
the EC2 fleet uses; if this works, `/browser/{i}` on EC2 works.

## Stage 3 — the full content_proxy stack, locally

```bash
sg content-proxy local up --browsers 2 --browser-engine chromium
# open  https://localhost/browser/1/  and  /browser/2/
# in the visible browser, load any http:// site → the mitm transform markers
#   (the XXX'd text) must render — proves browser → mitmproxy-int → interceptor.
# also confirm /pw/ and / (vault) still serve.
sg content-proxy local down
```

This renders gitignored `docker-compose.generated.yml` + `Caddyfile.generated`
next to the committed files. The committed compose is untouched (drift-guarded).

## Stage 4 — CI publish (needed before EC2)

Run the pipeline (dev) with `force_image_rebuild=true`. Watch, in order:
`build-vnc-amd64` → **`integration-test-vnc-image`** (the pre-tag gate: preflight
suite on :8000, `:6080/vnc.html` 200, supervisorctl ×5, and a REAL headed
Chromium opened via `POST /desktop/browser`) → `push-vnc-manifest`
(`diniscruz/sg-playwright-vnc:<version>` + `:latest`). A VNC-side red never
blocks the base `sg-playwright` publish.

## Stage 5 — EC2 acceptance (the plan-§8 run)

```bash
sg content-proxy create --browsers 2 --with-aws-dns --wait
```

The wait table must go all-green, including the two new proofs:
`containers-up … cp-browser-1, cp-browser-2` and **`browser-http` OK — "noVNC
serving on all 2 browser(s)"** (docker-exec'd curl inside each container — Up
alone is not accepted).

Then, with `<fqdn>` from `sg content-proxy info`:

```bash
sg content-proxy smoke <stack>                  # transform chain unchanged
open https://<fqdn>/browser/1/                  # noVNC desktop, trusted cert, no warnings
open https://<fqdn>/browser/2/                  # second user
open https://<fqdn>/pw/                         # /pw unaffected
# in browser 1, load an http:// page → transform markers render (mitm path live)
```

Auth check (only if created with `--edge-auth`):

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<fqdn>/browser/1/        # → 401
open  https://<fqdn>/edge/auth?token=<access-token>                       # sets cp_access cookie
# reload /browser/1/ → 200. Programmatic: -H 'X-API-Key: <access-token>'.
```

Teardown + expiry:

```bash
sg content-proxy delete <stack>       # or let the 1h deadman terminate it —
                                      # it is armed FIRST in the boot script now
```

## When something fails

| Symptom | First command | Likely layer |
|---|---|---|
| `browser-http` WARN | `sg cp logs <stack> --source browser-1` | supervisord/xvfb/novnc inside the container (`browser-N` works for any index) |
| `containers-up` missing `cp-browser-*` | `sg cp logs <stack> --source boot` | image pull (does `sg-playwright-vnc:latest` exist on Docker Hub yet?) |
| noVNC loads, screen black | `docker exec cp-browser-1 supervisorctl status` (via SSM) | xvfb/openbox died; autostart may have fired before X was ready |
| desktop shows, no browser open | `sg cp logs <stack> --source browser-1` (grep `autostart-browser`) | the oneshot's `POST /desktop/browser` failed — check the API key env |
| pages load un-transformed | `sg cp logs <stack> --source mitmproxy-int` | proxy env not reaching the launch (should be impossible — env-only wiring) |
| `/browser/1/` 404/redirect loop at the edge | `sg cp logs <stack> --source caddy` | edge routes — compare against `Caddyfile.generated` from stage 3 |

## Out of scope here (still-open, tracked in the debrief)

Raw-IP HTTPS (`https://<ip>/` — browsers send no SNI for IPs) and the
`--with-aws-dns` NXDOMAIN follow-up. Use the FQDN path for this guide.
