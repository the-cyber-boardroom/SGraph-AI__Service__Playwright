# How to Run a Vault on Fargate in 3 Commands

`sg vault-app fargate` delivers a running vault container on AWS ECS Fargate.
Setup is a one-time cost; subsequent starts target under 30 s.

---

## Prerequisites

- AWS credentials configured (via `sg credentials` or `AWS_*` env vars)
- Docker installed locally (needed for the `IMAGE_MIRROR` setup phase)
- `SG_AWS__EC2__ALLOW_MUTATIONS=1` and
  `SG_VAULT_APP__FARGATE__ALLOW_MUTATIONS=1` set in your shell

---

## Step 1: One-time setup — VPC stack + Fargate cluster

The Fargate cluster needs a VPC with public subnets and a security group.
Slice 3 of `sg aws ec2` provisions both in a single command, and
`sg vault-app fargate setup create` auto-discovers them from the
`Stack=sg-vault-app-fargate-network` tag.

```bash
export SG_AWS__EC2__ALLOW_MUTATIONS=1
export SG_VAULT_APP__FARGATE__ALLOW_MUTATIONS=1

# 1a. VPC + IGW + RT + 2 public subnets + SG with default ingress rules
sg aws ec2 vpc create-stack \
  --name sg-vault-app-fargate-network \
  --yes

# 1b. Fargate cluster — subnets + SG auto-resolved from the VPC stack
sg vault-app fargate setup create --yes
```

Step 1b runs six phases in order (ECR → IAM → LOGS → CLUSTER → IMAGE_MIRROR →
TASK_DEF) and writes all configuration as tags on the ECS cluster. Takes 2–5
minutes the first time. Both commands are fully idempotent — safe to re-run.

If you already have your own VPC, pass `--subnets` and `--sg` explicitly to
opt out of auto-resolve (or use `--no-auto-network`):

```bash
sg vault-app fargate setup create \
  --subnets subnet-abc \
  --sg sg-xyz \
  --yes
```

To check what setup put in place without making any changes:

```bash
sg vault-app fargate setup status
sg vault-app fargate setup show
```

---

## Step 2: Start a vault

```bash
sg vault-app fargate start \
  --access-token my-token \
  --yes
```

Output (Rich panel):

```
╭─ vault-app on Fargate ────────────────────────────────────╮
│ slug          : dinis-tue                                 │
│ cluster       : vault-app                                 │
│ public ip     : 18.130.45.12                              │
│ vault url     : https://18.130.45.12:443                  │
│ access token  : my-token                                  │
│ task ready    :  4.2 s  (RunTask → RUNNING)               │
│ vault ready   :  9.7 s  (RunTask → 200 /info/health)      │
╰───────────────────────────────────────────────────────────╯
```

The slug auto-generates if `--slug` is omitted. The cluster auto-resolves to
the single cluster tagged `Stack=sg-vault-app-fargate` in the region.

For JSON output (useful for scripting):

```bash
sg vault-app fargate start --access-token my-token --yes --json
```

---

## Step 3: Use the vault

The `vault_url` printed in Step 2 is the reachable address. Use it directly
with the `sg` CLI or via HTTP:

```bash
sg vault-app fargate url        # re-print the URL for the running vault
sg vault-app fargate open       # open the URL in a browser
sg vault-app fargate health     # check /info/health
sg vault-app fargate logs       # tail CloudWatch logs
```

---

## Stopping a vault

```bash
sg vault-app fargate stop --yes
```

The ECS task is stopped. The cluster and all other infrastructure remain in
place for the next `start`.

---

## Teardown (remove all AWS resources)

```bash
sg vault-app fargate setup delete --yes
sg aws ec2 vpc delete-stack sg-vault-app-fargate-network --yes
```

The first command runs the setup phases in reverse order (TASK_DEF →
IMAGE_MIRROR → CLUSTER → LOGS → IAM → ECR). The ECR repo and its images are
deleted last.

The second tears down the VPC stack itself (SG → subnets → route table → IGW
→ VPC). Idempotent — safe to re-run; missing resources are skipped.

## Useful flags

| Flag | Effect |
|------|--------|
| `--cluster C` | Target a specific cluster (default: auto-resolve) |
| `--slug S` | Target a specific running vault (default: auto-resolve) |
| `--launch-type FARGATE_SPOT` | Use Spot capacity (cheaper; may be interrupted) |
| `--time` | Print per-phase timing breakdown after start |
| `--json` | Machine-readable output (all commands) |
| `--phase ECR` | Run only one setup phase |
