# Review — v0.2.29 Slice C + D + Foundation follow-up

**Lead: there is one critical regression on dev. The Foundation follow-up (`bcd33439`) overwrote the CLI implementations of Slices B, C, and D with stubs raising `NotImplementedError`.** The user-facing surface for `sg aws ec2 *`, `sg aws fargate *`, and `sg aws iam graph *` is non-functional today. The service classes survive in all three slices; only the CLI wiring was destroyed.

34 tests are failing on dev as of `7632be55`. End-to-end CLI proof:

```
$ sg aws ec2 list
  ❱ raise NotImplementedError(_SLICE)
$ sg aws fargate cluster-list
  ❱ No such command 'cluster-list'.
$ sg aws iam graph discover
  ❱ raise NotImplementedError(_SLICE)
```

## What happened (the regression)

| File | Pre-follow-up (Slice B/C/D) | After `bcd33439` (Foundation follow-up) | Lost |
|------|---:|---:|---:|
| `aws/ec2/cli/Cli__EC2.py` | 432 LOC, 11 verbs | 99 LOC, all stubs | **333 LOC of working CLI** |

| `aws/iam/graph/cli/Cli__Iam__Graph.py` | 409 LOC, 6 verbs (real bodies) | 69 LOC, all stubs | **340 LOC of working CLI** |

**Total: ~1028 LOC of working CLI replaced with `raise NotImplementedError(_SLICE)`.**

### Root cause

The Foundation follow-up commit message lists item **F-3** as:

> F-3: stub verb bodies added to all 8 surface CLIs (Bedrock + IAM Graph completed)

The original architect F-3 instruction was to add stubs to the **5 surfaces that had bare Typer apps** (S3, Fargate (at the time), Bedrock, CloudTrail, Creds, Observe, IAM-graph). By the time Foundation follow-up was authored, Slices B, C, and D had **already shipped real implementations** for EC2, Fargate, and IAM-graph. F-3 should have skipped those three.

Instead, the follow-up applied F-3 indiscriminately and overwrote the live impls. The service classes (`EC2__AWS__Client`, `Fargate__AWS__Client`, `Iam__Graph__Builder`, etc.) survived because they weren't touched — only the `Cli__*.py` files were rewritten.

### What's still salvageable

**The service-layer code for all three slices is untouched.** Confirmed:

## Slice D (IAM graph) — issues independent of the regression

Reviewing what Slice D originally shipped (commit `3e260268` — recoverable from git, pre-regression):

### HD-1 — Tests use `monkeypatch` extensively (20 calls) — CLAUDE.md "no patches" violation

```python
# tests/unit/sgraph_ai_service_playwright__cli/aws/iam/graph/cli/test_Cli__Iam__Graph.py
monkeypatch.setattr(
    'sgraph_ai_service_playwright__cli.aws.iam.graph.cli.Cli__Iam__Graph._default_writer',
    lambda: writer)
```

CLAUDE.md is explicit: **"No mocks. No patches."** (rule #1 under Testing). Every other slice in v0.2.29 uses the in-memory composition pattern (Slice B uses `EC2__AWS__Client__In_Memory`; Slice C uses an equivalent).

**Fix:** replace `monkeypatch` with the in-memory composition pattern. Example:

```python
# Don't:
monkeypatch.setattr('...Cli__Iam__Graph._default_writer', lambda: writer)
runner.invoke(graph_app, ['snapshots', '--list'])

# Do:
from sgraph_ai_service_playwright__cli.aws.iam.graph.service.Iam__Graph__Vault__Writer import Iam__Graph__Vault__Writer
# pass writer via a documented seam — either:
# (a) a Typer context object (`@app.callback` to construct + inject)
# (b) an environment variable the verb consults (e.g. SG_AWS__IAM_GRAPH__WRITER_BASE_PATH)
# (c) a constructor-injected service that the test composes directly
```

Even before the regression-restore, this needs fixing. The pattern Slice B uses (`EC2__AWS__Client__In_Memory(EC2__AWS__Client)` subclass override) is the canonical way — adopt it in Slice D.

### HD-2 — CLI uses module-level `_default_writer()` / `_default_orchestrator()` helpers

Looking at the (recoverable) commit `3e260268`, Slice D's CLI relied on these module-level helpers as injection points for tests. The pattern works but is non-standard for this repo (other surfaces inject via `__init__` constructors on Type_Safe classes). Reconsider when restoring — better to use the same pattern as Slice B (an `In_Memory` subclass override) so future readers don't see two divergent injection styles in the same milestone.

### MD-1 — `Iam__Graph__Vault__Writer` writes to local disk despite locked decision #15

Locked decision #15 (umbrella `README.md`) says:

> No vault integration in this milestone. Slices E/G/H land local-file artefacts under `~/.sg/aws/<surface>/` (same shape, same 0600 perms as the v0.2.28 credentials store).

Slice D writes IAM graph snapshots to a `base_path` (tests use `tmp_path`). The class name says "Vault Writer" but the impl is local-file. Either:
- (A) Rename to `Iam__Graph__Local__Writer` (matches decision #15 and what Slices E/G/H are supposed to ship), OR
- (B) Keep the name but document that "vault" here means "the future vault home; for now writes locally under `~/.sg/aws/iam-graph/`"

The name `Iam__Graph__Vault__Writer` will mislead readers into thinking we have vault integration that we don't.

### MD-2 — Service-layer tests pass cleanly (23 of 32 — the non-CLI tier)

Despite the CLI test problems, the service-layer tests for `Iam__Graph__Builder`, `Iam__Discovery__Orchestrator`, `Iam__Graph__Cleanup`, `Iam__Graph__Filter`, `Iam__Graph__Snapshot__Diff`, `Iam__Graph__Walker` all pass. The Sonnet built solid service classes — the wiring problems are at the CLI/test boundary.

## Open question for the orchestrating Sonnet

The Foundation follow-up author appears to have re-written `Cli__EC2.py` etc. from scratch rather than reading the on-disk content. **Likely cause:** the Sonnet session that authored `bcd33439` was forked off the pre-Slice-B / pre-Slice-C / pre-Slice-D state and wasn't told that Slices B/C/D had already landed on dev. The brief explicitly says (decision #14 + Foundation §3): *"Foundation owns the stubs; slices fill them in."* When Foundation re-runs after slices have already filled in, the Sonnet needs to know "skip surfaces that have real implementations."

**Process recommendation:** before any future Foundation-style sweep, the orchestrating session should grep `grep -l "@app.command\|@.*_app.command" sgraph_ai_service_playwright__cli/aws/<surface>/cli/*.py` for each surface and **skip** those that already have real verbs. A one-line check would have prevented this regression.
