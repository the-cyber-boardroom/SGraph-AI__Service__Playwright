# Review — v0.2.29 Slices A/E/F/H + regression recovery

**Headline:** the regression I flagged in the prior review has been fixed cleanly. Four more slices (A/E/F/H) shipped substantial implementations. **622 unit tests pass across all `aws/*` (up from 588 last review).** Only Slice G remains.

The longer this goes uncorrected, the larger the eventual fix-up gets.

## ⚠️ Pattern-propagation issues (now systemic across slices)

### HCD-1 — Direct `boto3.client(...)` has spread to 9 service clients across 6 slices

The H-1 issue I raised in my [Slice B review](v0.2.29__slice-b-ec2__review.md) was not addressed, and the pattern has now been copied verbatim into every subsequent slice. Current state:

```
$ grep -l "^import boto3" sgraph_ai_service_playwright__cli/aws/*/service/*.py
sgraph_ai_service_playwright__cli/aws/s3/service/S3__AWS__Client.py                         (Slice A)
sgraph_ai_service_playwright__cli/aws/bedrock/service/Bedrock__Agent__AWS__Client.py        (Slice E)
sgraph_ai_service_playwright__cli/aws/bedrock/service/Bedrock__Control__AWS__Client.py      (Slice E)
sgraph_ai_service_playwright__cli/aws/bedrock/service/Bedrock__Runtime__AWS__Client.py      (Slice E)
sgraph_ai_service_playwright__cli/aws/bedrock/service/Bedrock__Tool__AWS__Client.py         (Slice E)
sgraph_ai_service_playwright__cli/aws/cloudtrail/service/CloudTrail__AWS__Client.py         (Slice F)
sgraph_ai_service_playwright__cli/aws/fargate/service/Fargate__AWS__Client.py               (Slice C)
sgraph_ai_service_playwright__cli/aws/ec2/service/EC2__AWS__Client.py                       (Slice B)
sgraph_ai_service_playwright__cli/aws/ec2/service/EC2__Pricing__Client.py                   (Slice B)

$ grep -l "Sg__Aws__Session\|boto3_client_from_context" sgraph_ai_service_playwright__cli/aws/*/service/*.py
(no matches — zero slices route through the credentials seam)
```

**The implication is real and easy to demonstrate:** run `sg credentials switch dev-role-eu-west-2` to activate a role configured for `eu-west-2`, then run `sg aws s3 bucket-list`. The bucket list returned is **not** the dev-role's buckets and **not** scoped to `eu-west-2`. It's whatever the bare boto3 credential chain picks up. The v0.2.28 credentials work + cached account_id + role region threading are bypassed by every new surface.

**Why the propagation happened:** Slice B's `EC2__AWS__Client.py` shipped with this pattern. Slices A/C/E/F all followed the same shape, including the `# EXCEPTION — see module header` comment. Slice E even has it across **four** clients in the same package.

**Fix shape** (the same one I suggested in the Slice B review — apply once, propagate to all 9 clients):

```python
from sgraph_ai_service_playwright__cli.credentials.service.Sg__Aws__Session import Sg__Aws__Session


class <Surface>__AWS__Client(Type_Safe):
    session : Sg__Aws__Session = None

    def setup(self):
        if self.session is None:
            self.session = Sg__Aws__Session.from_context()
        return self

    def client(self):                                                           # Single seam; In_Memory subclass overrides
        return self.session.boto3_client_from_context('<service>', region=...)
```

Estimated effort: ~10 LOC per client × 9 clients = ~90 LOC. The In-memory subclasses (which override `client()`) don't change. **One small commit fixes 6 slices at once.**

### HCD-2 — `monkeypatch` propagation across CLI tests (119 calls in 5 files)

CLAUDE.md is explicit: **"No mocks. No patches."** The current state on dev:

```
Slice B EC2          : 32 monkeypatch calls   tests/.../aws/ec2/cli/test_Cli__EC2.py
Slice C Fargate      : 45 monkeypatch calls   tests/.../aws/fargate/cli/test_Cli__Fargate.py
Slice D IAM graph    : 20 monkeypatch calls   tests/.../aws/iam/graph/cli/test_Cli__Iam__Graph.py
Slice F CloudTrail   : 22 monkeypatch calls   tests/.../aws/cloudtrail/cli/test_Cli__CloudTrail.py
Existing IAM         : 12 monkeypatch calls   tests/.../aws/iam/cli/test_Cli__Iam.py
                       ───
                       131 total
```

**Slices A / E / H tests use zero `monkeypatch`** — they follow the canonical in-memory composition pattern (subclass the AWS client, override the single boto3 seam). That pattern exists and works. The slices that used `monkeypatch` were copying the wrong example (the existing `aws/iam/cli/test_Cli__Iam.py` predates v0.2.29 and uses it — that's where the pattern leaked from).

**Fix shape:** for each of the 4 v0.2.29 CLI test files using `monkeypatch`, replace the monkeypatch pattern with an in-memory composition fixture. For example in Slice C:

```python
# Before
def test_cluster_list(monkeypatch, tmp_path):
    monkeypatch.setattr(
        'sgraph_ai_service_playwright__cli.aws.fargate.cli.Cli__Fargate._default_client',
        lambda: Fargate__AWS__Client__In_Memory(...))
    result = runner.invoke(app, ['cluster-list'])

# After (canonical for this repo)
def test_cluster_list(tmp_path):
    in_memory = Fargate__AWS__Client__In_Memory(...)
    # Either: inject via Typer @app.callback that takes a context object holding the client
    # Or:     env-var the verb consults (e.g. SG_AWS__FARGATE__CLIENT_FACTORY=tests.path.fixture)
    # Or:     module-level rebind (still arguably a patch — avoid)
    result = runner.invoke(app, ['cluster-list'], obj={'fargate_client': in_memory})
```

The CLI tests in Slices B/C/D/F all relied on `_default_*` module-level helpers to be monkeypatched. **The cleaner injection seam** is what Slice A and Slice E use (no module-level helpers; the CLI constructs the client at call time inside the verb body; the in-memory subclass either overrides via Typer context or via a subclass-replaced `_client()` callable). Bringing Slices B/C/D/F to that pattern is ~1-2 days of test refactoring.

**Why this matters beyond "violates CLAUDE.md":** `monkeypatch` couples tests to internal module structure (`_default_writer`, `_default_client`). When the CLI is reorganised (which it will be — there's a v0.2.30 hygiene pack coming), every `monkeypatch.setattr('...module-path...')` call breaks. The in-memory composition pattern doesn't.

### HCD-3 — Foundation's `Aws__Region__Resolver` + `Aws__Confirm` are dead code

```
$ grep -rln "Aws__Region__Resolver" sgraph_ai_service_playwright__cli/aws/
sgraph_ai_service_playwright__cli/aws/_shared/Aws__Region__Resolver.py     (only Foundation itself)

$ grep -rln "confirm_or_abort" sgraph_ai_service_playwright__cli/aws/
sgraph_ai_service_playwright__cli/aws/_shared/Aws__Confirm.py              (only Foundation itself)
```

Zero slices use either helper. `--region` flags appear in some verbs but use raw arg passing rather than the resolver. Confirmation prompts use raw `typer.confirm(..., abort=True)` everywhere instead of `confirm_or_abort` — which means **`--dry-run` doesn't exist on any mutating verb across any slice.**

The brief (Foundation §3.4) said: *"Mutating verbs default to `[y/N]` prompts. `--yes` / `-y` skips the prompt. **`--dry-run` skips execution entirely and prints the would-be call.**"* Half of that is honoured; the dry-run half is not.

**Fix shape:** sweep every mutating verb across the 6 slices that have mutating commands (B/C/E/F-no/D/G), replace `typer.confirm(..., abort=True)` with:

```python
if not confirm_or_abort(f'Stop instance {target!r}?', yes=yes, dry_run=dry_run):
    raise typer.Exit(0)
```

Add `--dry-run` option to each. ~3 LOC per mutating verb × ~15-20 mutating verbs = ~60 LOC. Same commit as HCD-1.

### MH-1 (Slice H) — Only 2 raw-`str` schema fields

`Schema__Observe__Source__Status` has 2 raw `str` fields (probably `name` and `status`). Worth adding `Enum__Observe__Source__Status` (UP / DOWN / DEGRADED) and `Safe_Str__Observe__Source__Name`.

### Slice E (Bedrock) — clean schemas (0 raw-str)

Good. Worth using as the reference for the others.

### MH-2 — `agent-trace` correlation ID name

The brief talks about correlating via `sg:session-id` (the Foundation tag from F-4). The implementation uses "session correlation ID" — same thing semantically. Worth wiring the tag explicitly so the user can run `sg aws ec2 create --session-id <id> ...` and then `sg aws observe agent-trace <id>` joins across S3 + CloudTrail + CloudWatch using that exact tag value. Currently the CLI verbs don't accept `--session-id`; that's a small follow-up.
