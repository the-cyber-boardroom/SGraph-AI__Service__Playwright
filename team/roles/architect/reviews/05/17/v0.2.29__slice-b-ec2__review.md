## HIGH-severity (must fix before merging more slices)

### H-1 — CLAUDE.md rule #14 / locked decision #3 violation: direct `boto3.client('ec2')`

**Locked decision #3** (umbrella `README.md`):

> Every AWS call routes through `osbot-aws` or an existing/new `*__AWS__Client` class that **wraps `Sg__Aws__Session`**. No direct boto3. The narrow exceptions documented in CLAUDE.md rule #14 stand; no new ones.

**What Slice B ships** (`aws/ec2/service/EC2__AWS__Client.py`):

```python
import boto3                                                                    # direct boto3 seam — narrow surface; each method only touches its own API call

class EC2__AWS__Client(Type_Safe):

    def client(self):                                                           # Single seam — subclass overrides for in-memory tests
        return boto3.client('ec2')
```

And in `EC2__Pricing__Client.py`:

```python
import boto3

class EC2__Pricing__Client(Type_Safe):

    def client(self):                                                           # Pricing API lives exclusively in us-east-1
        return boto3.client('pricing', region_name='us-east-1')
```

The comment at the top of `EC2__AWS__Client.py` literally acknowledges it ("direct boto3 seam"). The locked decision exists precisely to prevent this.

**Why this is a regression worth blocking on**

The v0.2.28 credentials work (`Sg__Aws__Session`, `account_id_for`, `account_id_from_context`, region threading from `Schema__AWS__Role__Config`) is **bypassed entirely**. Run `sg credentials switch dev` to activate a role, then `sg aws ec2 list` — boto3's default credential chain is used, not the role's. The cached account_id is unused. The role's region is unused.

This sets a precedent for the other 7 slices. If Slice B can do `boto3.client(...)`, Slice A (S3), C (Fargate), E (Bedrock), F (CloudTrail) will all do the same. That's the regression we promised v0.2.28 would prevent.

**Fix shape** (no extra abstraction needed):

```python
from sgraph_ai_service_playwright__cli.credentials.service.Sg__Aws__Session import Sg__Aws__Session


class EC2__AWS__Client(Type_Safe):
    session : Sg__Aws__Session = None

    def setup(self):
        if self.session is None:
            self.session = Sg__Aws__Session.from_context()
        return self

    def client(self):                                                           # Single seam — In_Memory subclass overrides
        return self.session.boto3_client_from_context('ec2')
```

`Sg__Aws__Session.boto3_client_from_context` already handles: active sg role → role's credentials + region, else fall through to bare boto3. The In-memory test subclass overrides `client()` directly — pattern unchanged.

Apply the same fix to `EC2__Pricing__Client`:

```python
def client(self):
    return self.session.boto3_client_from_context('pricing', region='us-east-1')
```

### H-3 — `Aws__Region__Resolver` is not used

Foundation ships `Aws__Region__Resolver` with the precedence (post-architect-review): flag > AWS_REGION > **active sg role's region** > resource hint > SG_AWS__DEFAULT_REGION > us-east-1.

Slice B does not call it. `boto3.client('ec2')` resolves region via boto3 defaults (~/.aws/config, AWS_DEFAULT_REGION env, IMDS). The active sg role's region is silently ignored.

**Fix:** once H-1 is in (`session.boto3_client_from_context` routes through the credentials store), `Sg__Aws__Session._make_base_session` already passes `region_name=str(config.region)`. So **H-1 fix subsumes H-3**. After H-1: pass `--region` from the CLI through to `client(region=...)` and let `Aws__Region__Resolver.resolve(--region-flag)` decide. One-line change in each verb.

## MEDIUM-severity

### M-1 — Silent exception masking on every mutation

```python
def start_instance(self, instance_id: str) -> bool:
    try:
        self.client().start_instances(InstanceIds=[instance_id])
        return True
    except Exception:
        return False
```

Same shape for `stop_instance`, `terminate_instance`, `create_instance` (returns `None`), `add_tags`, `remove_tags`, `describe_instance` (returns `None`).

The CLI does `if ok: green-print, else: red-print "Failed to start"` — caller sees "Failed" with no AWS error message. Was it permission denied? Wrong region? Instance doesn't exist? Throttled? **All look identical from the caller's perspective.**

**Fix:** either propagate the original exception (let typer's exception handler render it) or translate into a typed error:

```python
def start_instance(self, instance_id: str) -> None:
    self.client().start_instances(InstanceIds=[instance_id])  # raises botocore.ClientError on failure
```

Then in the CLI:

```python
try:
    _client().start_instance(iid)
except botocore.exceptions.ClientError as exc:
    console.print(f'[red]Start failed:[/red] {exc.response["Error"]["Message"]}')
    raise typer.Exit(1)
console.print(f'[green]Started[/green] {iid}')
```

Or: introduce a `Schema__AWS__Error` and the existing `AWS__Error__Translator` (from `elastic/`) — but the bare propagation works fine for v0.2.29.

### M-2 — AMI alias resolution NOT implemented

Slice B brief §"Risks to watch":

> **AMI alias drift.** Aliases like `ubuntu-22.04-arm64` resolve to different IDs per region and over time. Cache resolutions for the session; expose `--ami-id` to bypass alias resolution.

The `Safe_Str__EC2__AMI_Id.py` docstring even claims:

> Also accepts alias strings (e.g. 'ubuntu-22.04-arm64') for the resolver.

But there's **no resolver**. A user running `sg aws ec2 create --ami ubuntu-22.04-arm64 ...` will pass that literal string to `run_instances(ImageId='ubuntu-22.04-arm64')` and AWS will reject it (InvalidAMIID.Malformed).

**Fix:** either add `EC2__Ami__Resolver` per the brief (~50 LOC: SSM Parameter Store lookup for Ubuntu/AL2/AL2023 aliases, in-memory cache) — or remove the alias claim from the primitive docstring and the brief, and only document literal `ami-xxxx` IDs.

### M-3 — `Schema__EC2__Create__Request` uses raw `str` everywhere

```python
class Schema__EC2__Create__Request(Type_Safe):
    name             : str                          = ''
    instance_type    : Safe_Str__EC2__Instance__Type
    ami_id           : Safe_Str__EC2__AMI_Id
    key_pair         : str                          = ''
    subnet_id        : str                          = ''
    security_groups  : str                          = ''    # comma-separated SG IDs
    user_data        : str                          = ''
    extra_tags_raw   : str                          = ''
    wait_for_running : bool                         = True
```

CLAUDE.md rule #2: "Zero raw primitives — no `str`, `int`, `float`, `list`, `dict` as attributes."

Two of the seven schema strings (`name`, `key_pair`, `subnet_id`, `security_groups`, `user_data`, `extra_tags_raw`) are bare `str`. Should be `Safe_Str__EC2__Name`, `Safe_Str__EC2__Key_Pair__Name`, `Safe_Str__EC2__Subnet_Id`, `List__Safe_Str__EC2__SG_Id`, etc. The other surfaces (Slices A/C/D/E/F/G/H) will look here for the pattern — wrong pattern propagates.

**Fix:** add the missing primitives (~5 small files), retype the schema. `user_data` can stay `str` (script body, no validation possible).

### M-4 — Dead field `Schema__EC2__Create__Request.extra_tags_raw`

```python
extra_tags_raw   : str  = ''    # JSON string of extra k=v pairs
```

Grep across the slice — nothing reads or writes it. Even `ec2_create` in the CLI builds `sg_tags` and passes it via the separate `extra_tags=sg_tags` kwarg to `client.create_instance()`. Delete the field.

### M-5 — `Schema__EC2__Instance__Detail.tags_raw / security_groups_raw / block_devices_raw : str` — JSON-encoded escape hatches

```python
tags_raw             = json.dumps(tags),
security_groups_raw  = json.dumps(raw.get('SecurityGroups', [])),
block_devices_raw    = json.dumps(raw.get('BlockDeviceMappings', [])),
```

The CLI then does `json.loads(detail.tags_raw)` to render. This is abandoning Type_Safe at the boundary — the schema becomes a typed bag of untyped JSON strings.

**Fix:** introduce typed schemas:

```python
class Schema__EC2__Security_Group__Ref(Type_Safe):
    group_id   : Safe_Str__EC2__SG_Id
    group_name : Safe_Str__AWS__Tag_Value

class Dict__EC2__Tag(Type_Safe__Dict):
    expected_key_type   = Safe_Str__AWS__Tag_Key
    expected_value_type = Safe_Str__AWS__Tag_Value

class List__Schema__EC2__Security_Group__Ref(Type_Safe__List):
    expected_type = Schema__EC2__Security_Group__Ref
```

Then `Schema__EC2__Instance__Detail.tags : Dict__EC2__Tag`, `security_groups : List__Schema__EC2__Security_Group__Ref`. Block devices are more complex but the same shape applies.

### M-6 — ssh-info user detection is naive

```python
user = 'ec2-user'                                              # Amazon Linux / AL2023 default
if 'ubuntu' in str(detail.ami_id).lower() or 'ubuntu' in detail.name.lower():
    user = 'ubuntu'
```

Misses: Debian (`admin`), Bitnami (`bitnami`), CentOS (`centos`), Fedora (`fedora`), CoreOS (`core`), Kali (`kali`). The brief said "username (per AMI)" — implies a real lookup, e.g. via the AMI's `PlatformDetails` field (which is in the boto3 describe-images response) or a small alias table.

**Fix (v1):** Use `detail.platform` if it's `'Linux'` or `'windows'`, then a small alias dict keyed on AMI-name prefix. Acceptable to defer to v2 if documented.

### M-7 — `_shared/Aws__Region__Resolver` is unused; CLI verbs don't expose `--region`

Aside from the H-3 plumbing issue, **no `sg aws ec2 *` verb takes a `--region` flag**. The Slice B brief mentions `--region` for `pricing` (present) but `list / describe / create` should also accept it. Brief §"Verbs" table includes "`--region`" on `list`. Missing.

**Fix:** add `--region/-r` to all verbs; pass through to `_client(region=...)` which threads to `Sg__Aws__Session.boto3_client_from_context('ec2', region=region)`.

### M-8 — Foundation `Aws__Confirm.confirm_or_abort` is not used

Slice B uses `typer.confirm(f'Stop instance {target!r}?', abort=True)` directly. The `Aws__Confirm` helper exists in Foundation specifically to give uniform `--yes / --dry-run` behaviour. Slice B implements `--yes` itself but doesn't support `--dry-run`.

**Fix:** Replace inline `typer.confirm` with `confirm_or_abort(message, yes=yes, dry_run=dry_run)`, add `--dry-run` to mutating verbs.

### L-1 — `EC2__AWS__Client` header comment is aspirational, not accurate

> Wraps osbot_aws EC2 helpers where available; falls back to a direct boto3 client() seam for operations not yet in osbot_aws.

Grep the file — no `osbot_aws` import. Update the comment to match reality (or use osbot_aws — `from osbot_aws.aws.ec2.EC2 import EC2` for some calls).

### L-2 — `ec2_list` JSON output omits `ami_id`

```python
typer.echo(json.dumps([dict(instance_id  = str(i.instance_id),
                            name         = i.name,
                            instance_type= str(i.instance_type),
                            state        = str(i.state),
                            public_ip    = i.public_ip,
                            private_ip   = i.private_ip,
                            launch_time  = i.launch_time,
                            key_name     = i.key_name) for i in instances], indent=2))
```

`Schema__EC2__Instance` has `ami_id` — should be in the JSON output for scripting.

**Better fix:** stop hand-rolling JSON. The schema has `.json()` from Type_Safe. `json.dumps([i.json() for i in instances])` — single line, can never drift from the schema.

### L-3 — `_region_long_name` hardcoded region map

Hardcoded mapping of ~16 regions. AWS adds regions periodically. Worth a TODO marker; or use AWS's own pricing-region SSM parameter (`/aws/service/global-infrastructure/regions/<short>/longName`).

### L-4 — `tags` verb doesn't filter `sg:*` from user-set deletions

`sg aws ec2 tags <id> --clear` deletes ALL tags, including the `sg:managed-by` / `sg:created-by` / `sg:surface` ones Foundation's tagger added at creation. A `--clear` shouldn't strip the canonical SG-managed tags (they're the substrate for Slice H's observability correlation).

**Fix:** when `--clear` or `--remove`, filter out keys starting with `sg:` unless `--include-sg-tags` is also passed.

### L-5 — `Cli__EC2.py` imports `from typing import List, Optional` but the codebase elsewhere uses `list | None` style (PEP 604)

Cosmetic; consistency with other slices. Not blocking.

## What I'm explicitly NOT flagging (and why)

- **Coverage of `_parse_summary` / `_parse_detail` edge cases** — current tests via the In_Memory client cover happy path; AWS-edge-case coverage is a v0.3 hardening item, not a v0.2.29 ship-blocker.

- **The `wait` backoff schedule** (2s→5s→10s→15s) — matches the brief exactly. Fine.
- **`EC2__Name__Resolver`'s prefix-fallback behaviour** — accepts exact match first, falls back to prefix match if zero exact. Brief said exact + ambiguity error; the prefix fallback is a minor extension but the ambiguity error still applies. Acceptable.
