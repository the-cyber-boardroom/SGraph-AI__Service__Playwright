# Handover Brief — same-origin reverse proxy in the `sg-send-vault` container

> **Audience:** the `SGraph-AI__App__Send` dev team. This is self-contained — all paths
> below are in **your** repo unless prefixed `[playwright-repo]`.

## 1. Why

The `sg va create --with-playwright` stack runs four containers on one EC2 host:
`sg-send-vault` (your app, `:443` HTTPS), `sg-playwright` (`:80` HTTP), `agent-mitmproxy`,
`host-plane` — all on the `vault-net` docker bridge. A script in the vault browser page
(`https://<ip>`) cannot call the Playwright API at `http://<ip>` — the browser blocks it as
**mixed content**, and the vault must stay HTTPS (Web Crypto / secure-context).

**Fix:** mount a same-origin reverse proxy on the vault FastAPI so
`https://<ip>/pw/{path}` forwards internally to `http://sg-playwright:8000/{path}`. Because
it is same-origin: no mixed-content block, no CORS, it rides your existing auth middleware,
and it stays on `:443` (the Claude sandbox only allows `:80`/`:443`). No new container.

## 2. Exactly where it goes in your repo

| Concern | Location |
|---------|----------|
| Composition root | `sgraph_ai_app_send__docker/Fast_API__SGraph__Send__Container.py` → `setup_routes()` |
| New single-file class | `sgraph_ai_app_send__docker/Fast_API__Reverse_Proxy.py` (mirror your `Fast_API__TLS__Launcher.py` convention — vendored, dependency-light, slated for OSBot__Fast_API upstream) |
| TLS entrypoint (unchanged) | `sgraph_ai_app_send__docker/serve.py` |
| Image build | `.github/workflows/ci-pipeline.yml` → `publish-to-dockerhub` job (`DOCKERHUB_IMAGE: diniscruz/sg-send-vault`); run with `should_publish_dockerhub=true` |

The global API-key middleware is added in `setup()` via `enable_global_auth()` and applies
to the whole app, so `/pw/*` routes are auth-gated automatically — the in-page script
already authenticates to the vault with the `x-sgraph-access-token` cookie, so its `/pw/*`
calls carry the same auth with no extra work.

### 2.1 Why the container subclass, not the base `lambda__user` app

The base FastAPI app — `sgraph_ai_app_send/lambda__user/fast_api/Fast_API__SGraph__App__Send__User.py`
(extends `Serverless__Fast_API`) — is shared by **two** deployment targets: the AWS Lambda
(`sgraph_ai_app_send/lambda__user/lambda_function/lambda_handler__user.py`) **and** the
docker container (`Fast_API__SGraph__Send__Container` subclasses it). The reverse proxy is
meaningful **only in the 4-container EC2 stack** — that is the only place a `sg-playwright`
sibling exists on `vault-net` to proxy to. In Lambda there is no sibling and no
`vault-net`. So the mount belongs in the **container subclass**
(`sgraph_ai_app_send__docker/Fast_API__SGraph__Send__Container.setup_routes()`), keeping the
base/Lambda path untouched. (It is env-guarded and would be a harmless no-op in the base
too, but scoping it to the container is the correct boundary.)

## 3. Drop-in implementation

### 3.1 New file — `sgraph_ai_app_send__docker/Fast_API__Reverse_Proxy.py`

Generalised from the playwright repo's proven `Routes__Web` reverse-proxy
(`[playwright-repo] sg_compute_specs/mitmproxy/api/routes/Routes__Web.py`). Single file,
`httpx` lazy-imported (same discipline as your TLS launcher lazy-importing uvicorn).

```python
# Vendored single-file reverse proxy. Mirrors Fast_API__TLS__Launcher.py — destined
# for OSBot__Fast_API upstream; keep dependency-light so the de-dupe is mechanical.
#
# Env contract:
#   FAST_API__REVERSE_PROXY__ROUTES   "pw=http://sg-playwright:8000,mitm=http://agent-mitmproxy:8081"
#   (comma-separated  <prefix>=<upstream_base_url>  entries; empty/unset → no-op)
import os
from fastapi                                       import Request
from fastapi.responses                             import Response
from osbot_utils.type_safe.Type_Safe               import Type_Safe

ENV_VAR__ROUTES   = 'FAST_API__REVERSE_PROXY__ROUTES'
ENV_VAR__TOKEN    = 'SGRAPH_SEND__ACCESS_TOKEN'                 # injected as X-API-Key to upstream
UPSTREAM_API_KEY  = 'X-API-Key'
ALL_METHODS       = ['GET', 'POST', 'PUT', 'DELETE', 'HEAD', 'OPTIONS', 'PATCH']
STRIP_REQUEST     = {'host', 'content-length', 'x-sgraph-access-token', 'cookie'}
HOP_BY_HOP        = {'content-length', 'transfer-encoding', 'connection', 'keep-alive'}
TIMEOUT_SEC       = 120.0                                       # > Playwright sequence runs


class Fast_API__Reverse_Proxy(Type_Safe):

    def parse_routes(self) -> dict:                            # {prefix: upstream_base_url}
        raw = os.environ.get(ENV_VAR__ROUTES, '').strip()
        out = {}
        for entry in (e for e in raw.split(',') if e.strip()):
            prefix, _, upstream = entry.partition('=')
            prefix, upstream = prefix.strip().strip('/'), upstream.strip().rstrip('/')
            if prefix and upstream:
                out[prefix] = upstream
        return out

    def mount(self, app):
        token = os.environ.get(ENV_VAR__TOKEN, '')
        for prefix, upstream in self.parse_routes().items():
            self._mount_one(app, prefix, upstream, token)

    def _mount_one(self, app, prefix, upstream, token):
        from fastapi import APIRouter
        router = APIRouter()

        async def proxy(request: Request, path: str = ''):
            import httpx
            url     = f'{upstream}/{path}' if path else f'{upstream}/'
            headers = {k: v for k, v in request.headers.items()
                       if k.lower() not in STRIP_REQUEST}
            if token:
                headers[UPSTREAM_API_KEY] = token                # translate vault auth → upstream auth
            headers['X-Forwarded-Prefix'] = f'/{prefix}'         # Starlette upstreams honour this
            body = await request.body()
            async with httpx.AsyncClient(timeout=TIMEOUT_SEC) as client:
                r = await client.request(request.method, url, headers=headers,
                                         params=request.query_params, content=body or None)
            passthrough = {k: v for k, v in r.headers.items() if k.lower() not in HOP_BY_HOP}
            return Response(content=r.content, status_code=r.status_code,
                            headers=passthrough, media_type=r.headers.get('content-type'))

        router.add_api_route('/',            proxy, methods=ALL_METHODS)
        router.add_api_route('/{path:path}', proxy, methods=ALL_METHODS)
        app.include_router(router, prefix=f'/{prefix}')
```

### 3.2 Wire it in — `Fast_API__SGraph__Send__Container.setup_routes()`

```python
def setup_routes(self):
    super().setup_routes()
    self.add_routes(Routes__Set_Cookie)
    from sgraph_ai_app_send__docker.Fast_API__Reverse_Proxy import Fast_API__Reverse_Proxy
    Fast_API__Reverse_Proxy().mount(self.app())          # mounts /pw/* etc. from env; no-op when env unset
```

That is the entire change in your repo: one new file + two lines.

## 4. Decisions baked in (flag if you disagree)

- **Auth translation:** inbound `x-sgraph-access-token` (your middleware) is dropped before
  forwarding; the proxy injects `X-API-Key: $SGRAPH_SEND__ACCESS_TOKEN` to the upstream
  (same token value, already in the container env). The browser script needs to send
  *nothing* special — it's already authenticated to the vault.
- **Prefix safety:** your app uses `/`, `/_common`, `/en-gb`, `/i18n`, `/api/*`, `/info/*`,
  `/auth/*`. `/pw` is free. We use `app.include_router(prefix=…)`, **not** a catch-all
  `Mount('/')` — consistent with the warning already in your `setup_static_routes()`.
- **No-op by default:** with `FAST_API__REVERSE_PROXY__ROUTES` unset, `mount()` adds nothing.
  Safe to ship dark.
- **WebSockets not proxied** (httpx is request/response). The Playwright REST surface needs
  no WS; `host-plane`'s `/shell/stream` would, if ever added — out of scope for v1.

## 5. Who sets what

- **You (Send repo):** the new file + the two-line mount, then rebuild/push
  `diniscruz/sg-send-vault` via the `publish-to-dockerhub` job.
- **Us (`[playwright-repo]`):** we set the env value at launch —
  `FAST_API__REVERSE_PROXY__ROUTES=pw=http://sg-playwright:8000` is added to the vault
  container in `[playwright-repo] sg_compute_specs/vault_app/service/Vault_App__Compose__Template.py`.
  You only need the code that *reads* it.

## 6. Sub-path side effect (known, low-risk for v1)

Pure Playwright API calls (`/health`, `/sequence/execute`, `/browser/*`) are path-agnostic
and work under `/pw` immediately. Only the Playwright "/" index UI and `/openapi.json`
emit absolute URLs that would need the prefix. The proxy already sends
`X-Forwarded-Prefix: /pw`; the Playwright app (ours) honours Starlette `root_path`, so we
can make the UI prefix-correct on our side if/when it's needed. No action for you.
