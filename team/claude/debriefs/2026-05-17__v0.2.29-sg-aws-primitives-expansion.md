## 4. Failures

### 4.1 GOOD failure — Slice A worktree branch conflict (race condition caught early)

Slice A pushed commit `b6cdf05` to its worktree branch, not to `claude/aws-primitives-support-uNnZY`. This happened because the architect review commit (`688532e`) was pushed to the main branch AFTER Slice A had already pushed there, effectively orphaning Slice A's commit. Subsequent slice agents rebased on the post-review state and their commits landed correctly.

**Recovery:** `git cherry-pick b6cdf05` with conflict resolution (README merge + S3 files from Slice A took precedence).

**Lesson:** Worktree agents SOMETIMES push to the right branch (B, C, D, F, H did) and sometimes only to their worktree branch (A, E did). The coordinator must always check `git branch --all --contains <commit>` after each slice completion notification.

### 4.2 BAD failure — `git checkout --theirs` in rebase resolves WRONG side

During `git pull --rebase`, when resolving conflicts between my Foundation follow-up stubs and Slice agents' full implementations, I ran `git checkout --theirs`. In a `git rebase`, `--theirs` refers to the **commits being applied** (my stubs), NOT the upstream (the full implementations). This is the opposite of `git merge` semantics.

Result: EC2, Fargate, and IAM Graph CLIs were left with stub `raise NotImplementedError` bodies even though the slice agents had implemented them. All their tests failed. Fixed in `c4cc6ea` by restoring from `git show <slice-commit>:path/to/Cli__*.py`.

**Lesson baked in:** In `git rebase` conflict resolution:
- `--ours` = the upstream branch (what we're rebasing onto) — the FULL implementations from slice agents
- `--theirs` = the commits being applied (our local commit) — the Foundation stubs

Always use `git checkout --ours` to take the upstream full implementation when rebasing Foundation stubs onto slice implementations.

### 4.3 GOOD failure — `allow_empty=False` on `Safe_Str__AWS__Tag_Key`

Initial `Safe_Str__AWS__Tag_Key` had `allow_empty = False`, causing `Type_Safe` default construction to fail when creating `Schema__AWS__Tag()` with no args. Fixed to `allow_empty = True`. Caught by the `test_Aws__Tagger.py` tests immediately.

### 4.4 GOOD failure — Bedrock `yaml` not in poetry environment

`Bedrock__Model__Resolver` imports `yaml` (pyyaml) which was in `pyproject.toml` but not installed in the running environment. Required `poetry run pip install pyyaml`. The lock file needed regeneration. Tests reliably caught this at collection time.
