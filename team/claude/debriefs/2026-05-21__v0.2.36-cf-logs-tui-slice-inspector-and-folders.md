# v0.2.36 CF-logs TUI — Field Lineage Inspector + folder navigation

## 1. Why

Two user asks while driving `sp el lets cf tui files`: (1) **see the details of a loaded
file** down to the field level, and (2) **see more folders and files** (the demo only
showed the in-memory `fixtures.tsv`). This slice adds the Field Lineage Inspector and
turns the Files view into a real **folder browser** that walks the
`cloudfront-realtime/{YYYY}/{MM}/{DD}/{HH}/` partitions.

## 2. What landed

| Piece | Where | Note |

## 3. Key design decisions

- **Inspector is pure + reuses the parser.** `Record_Builder` runs the real
  `CF__Realtime__Log__Parser` and pairs each parsed field with its RAW TSV column, so
  the raw→transformed deltas (UA url-decode, `-`→normalized, status→`status_class`,
  bot classification) are shown honestly, computed not narrated.
- **Folder nav via one new seam method.** `list_dir(prefix)` returns folders + files at
  one level. S3 uses `list_objects_v2` with `Delimiter='/'` through the existing
  `S3__Inventory__Lister.s3_client` (no change to the LETS class); the call is wrapped
  in an overridable `list_objects_delimited` so tests inject results — no AWS, no mocks.
- **One screen, three modes, a prefix stack.** dir↔file↔record drill with Esc walking
  back up the folder tree — the natural "S3 browser" UX the user asked for.
- **Event-row selection** added to the file view so Enter on a row opens *that* event's
  lineage (event index ↔ Nth valid line, consistent with the parser's success filter).

## 4. Gotchas the next session will hit

- **Fixture path vs embedded timestamp.** The golden lines' real unix time is 2026-04-25;
  the demo places them under `…/2026/04/21/08/` for a tidy partition. Cosmetic only
  (clearly the in-memory fixture); the S3 source uses real keys/paths.
- **`list_objects_delimited` is the S3 seam to override in tests** (not `paginate`) — it
  returns `(folder_prefixes, objects)`.
- **Safe_Str transforms surface in the inspector** (e.g. `HTTP/2.0 → HTTP_2.0`): that is
  the real `Safe_Str__Text` sanitisation, shown honestly as a "changed" field.
