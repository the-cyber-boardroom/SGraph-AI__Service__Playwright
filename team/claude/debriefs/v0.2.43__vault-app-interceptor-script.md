## The ask

The `sg va create --with-playwright` mode reverse-proxies the Playwright service
through the vault at `/pw/*` and routes the browser's egress through an
`agent-mitmproxy` container. The request: let an operator supply a mitmproxy
**intercept script** for that proxy, file-based, at create time.

## What already existed (and what didn't)

- The 4-container stack (`Vault_App__Compose__Template`) ran a **vanilla
  `mitmproxy/mitmproxy:latest`** with a bare `mitmweb` command — no `--scripts`,
  no volume, nowhere to hook an interceptor. (It is *not* the custom
  `agent_mitmproxy` image with the addon registry / FastAPI admin.)
- The browser was *already* routed through it
  (`SG_PLAYWRIGHT__DEFAULT_PROXY_URL=http://agent-mitmproxy:8080` +
  `IGNORE_HTTPS_ERRORS`), so the only missing piece was the script seam.
- The **VNC** and **Firefox** specs already solved this exact problem the right
  way: mount an interceptors dir, run `mitmweb --scripts=…/active.py`, and write
  the resolved source to the host before `compose up`. The vault-app already
  uses an identical "write files to host → bind-mount → `compose up`" mechanism
  for its reverse-proxy override.

So this slice was a **pattern transplant**, not a new design.

## The change

Mirrors `Vnc__*` / `Firefox__*`:

1. `Enum__Vault_App__Interceptor__Kind` (`none` | `inline`) — file-only input, so
   no `name`-example surface was carried over (kept lean, per the scope decision).
2. `Safe_Str__Vault_App__Interceptor__Source` — printable-text primitive, 32 KiB cap.
3. `Schema__Vault_App__Interceptor__Choice` — `kind` + `inline_source`.
4. `Vault_App__Interceptor__Resolver.resolve()` → `(source, label)`; `none` →
   `NO_OP_SOURCE`, `inline` → source (raises on empty inline).
5. `Vault_App__Compose__Template._AGENT_MITMPROXY` — add
   `--scripts=/interceptors/active.py` + `/opt/vault-app/interceptors:/interceptors:ro`.
6. `Vault_App__User_Data__Builder.render_interceptor_block()` — write `active.py`
   (no-op stub when none) **before `compose up`**, only in the with-playwright shape.
7. `Vault_App__Service.create_stack` — resolve the choice, pass `interceptor_source`.
8. `Cli__Vault_App` — `--interceptor-script <file>`; `_set_extras` reads the local
   file and fills `request.interceptor` (kind=inline).
9. `Schema__Vault_App__Create__Request.interceptor` carries the choice.

mitmweb hot-reloads `--scripts` files on change, so this seam also unlocks a
future `set-interceptor`-over-SSM (swap the script on a running stack, no
recreate) — explicitly **out of scope** for this slice.

## Good failures

- **Caught the vanilla-image gap early.** The first read of
  `Vault_App__Compose__Template` showed the stack uses `mitmproxy/mitmproxy:latest`
  with no script seam — so the "interceptor support already exists" assumption
  (true for the custom `agent_mitmproxy` image and the VNC/Firefox stacks) did
  **not** hold here. Cross-checking the compose template against the reality doc
  before designing avoided wiring against the wrong image.
- **YAML inline-comment risk spotted before commit.** A `# comment` after a
  `command:` list item is valid YAML but brittle; moved it to a Python comment
  to keep the rendered compose clean (matches the VNC template style).

## Bad failures

- **Pre-existing unrelated test failure left as-is.**
