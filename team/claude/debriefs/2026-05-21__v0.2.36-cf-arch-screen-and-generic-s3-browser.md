# v0.2.36 — CF Deployed Architecture + generic S3 browser

Two requests in one: a **Deployed Architecture** screen for the CF-logs TUI, and an
**equivalent generic S3 bucket/folder/file browser + viewer**.

## 1. Deployed Architecture (cf tui)

`sp el lets cf tui architecture` — draws the live wiring Internet → CloudFront →
Firehose → S3 → LETS → consumers, plus CloudWatch log groups.

| Piece | Where |
|---|---|
| Source | `source/CF_TUI__Arch_Source` — enumerates via the existing `sg aws` clients (`CloudFront__AWS__Client.list_distributions`, `Logs__AWS__Client.list_log_groups`, `S3__AWS__Client.list_objects`); each read wrapped → a missing credential yields an honest error string, not a crash |
| Schemas | `Schema__CF_TUI__Arch_{Distribution,Log_Group,Snapshot}` (+ lists) |
| Render | `screens/CF_TUI__Arch__Render` — wiring diagram; **Firehose marked ⚠ UNVERIFIED** (no `sg aws` support) and each distribution's rt-log→Firehose link flagged UNVERIFIED (the reality-doc gap surfaced as UI) |
| Screen + CLI | `CF_TUI__Screen__Arch` + `architecture` command (`_arch_factory` test seam) |

Tested with fake clients (subclass + override the list methods) — no AWS, no mocks;
happy path + graceful cf-error path.

## 2. Generic S3 browser + viewer (new module `aws/s3/tui/`)

`sg aws s3 browse [s3://bucket/prefix]` — a content-agnostic browser for **any** bucket.

| Piece | Where |
|---|---|
| Source | `source/S3_Browser__Source` — wraps `S3__AWS__Client` (the sole boto3 boundary) + `S3__Format__Detector`: `list_buckets`, `list_dir` (Delimiter folders+files), `read_object` (gunzip .gz, hex-dump binary, 256 KB preview cap) |
| Schemas | `Schema__S3_Browser__Entry` (bucket/folder/file) + `__View` |
| Render | `screens/S3_Browser__Render` — entry list + object preview (Rich-escaped) + plain variants |
| Screen | `S3_Browser__Screen` — three levels **buckets → dir → object**, ↑/↓/Enter/Esc; optional `s3://bucket/prefix` start |
| CLI | `tui/cli/Cli__S3__Browser.run_browse` + one `@app.command('browse')` (lazy import) in the existing `Cli__S3` |

Tested with a fake `S3__AWS__Client` (override `list_buckets`/`list_objects`/
`get_object_body`) — no AWS, no mocks; text, gzip-decompress, and binary hex paths.

## 3. Key design decisions

- **Reuse the boundaries, don't add new ones.** Architecture reuses the three `sg aws`
  clients; the S3 browser reuses `S3__AWS__Client` + `S3__Format__Detector`. Both
  inject the client(s) so tests subclass-and-override the read methods.
- **Honesty as UI.** Architecture renders `⚠ UNVERIFIED` for the Firehose hop and
  per-distribution rt-log wiring, and shows per-source error lines rather than
  crashing when creds are absent.
- **Same thin-view discipline** — pure renders + source seam; textual lazy + gated.

## 4. Gotchas

- **Persisted shell CWD bites pytest.** A stray `cd …/aws/s3` left CWD inside a dir
  that has a `collections/` package, which shadowed stdlib `collections` and broke
  `python -m pytest` at startup. Always run from repo root.
- **Fake `get_object_body` should be keyed by object key, not (bucket, key)** — the
  browser screen reaches objects via real bucket names from `list_buckets`.
