# v0.2.36 Bedrock Chat TUI — T1 + S1–S4

A Textual chat TUI over `sg aws bedrock chat` (Nova-only), with per-turn and
per-session cost/token tracking as a first-class, always-visible concern. Built thin
over the existing bedrock primitives; the conversational widgets are written as a
reusable, provider-agnostic kit. Implements the pack delivered earlier in the session.

## Design decisions taken (open questions from the pack, resolved with the recommended answers)

- Single session (no tabs); `ctrl+l` clears the conversation **and** resets cost.
- Brief = assembled from the transcript (no extra LLM cost); LLM-synthesis is a later opt-in.
- Cost is in-memory only; nothing is written on exit — capture is the explicit `ctrl+b` brief / `ctrl+s` export.
- Nova-only: resolver/picker filtered to `nova`; the four aliases priced from the existing calculator.

## GOOD failures (caught by the pilot tests, before any human saw them)

1. **Message-handler name mangling.** `Chat__Composer.Submitted`'s auto handler is
   `on_chat__composer_submitted` (the `__` in the class name leaks into the snake-case
   namespace), so the conventional `on_chat_composer_submitted` never fired and Enter
   did nothing. Fixed by binding the message **by type** with `@on(Chat__Composer.Submitted)`.
   Lesson for this codebase: with the `Word__Word` class convention, prefer `@on(...)`
   over auto-named message handlers in any TUI.
2. **Focused TextArea swallows single-letter hotkeys.** With the composer focused for
   typing, `m`/`b`/`e` were typed as text instead of triggering actions. Fixed by moving
   global actions to Ctrl-combos + F1 that `TextArea` does not bind (verified against
   `TextArea.BINDINGS`) so they bubble to the App. Composer stays focused → "just type"
   UX preserved.

Both were surfaced immediately by `App.run_test()` pilot assertions — exactly the
no-mocks payoff the playbook bets on.

## BAD failures

None.

## Cost-accuracy note (the point of the tool)

Streaming previously reported `tokens = 0`. The TUI extracts the trailing `metadata`
event (`usage` + `metrics.latencyMs`) via `Bedrock__Stream__Adapter.collect_with_usage`,
so every turn shows exact tokens and an exact USD cost from the existing calculator —
streaming **and** accurate cost. The CLI `--stream` path can adopt the same method to
stop reporting zero.
