## 3. Key design decisions (the how)

- **Events are honest deltas, not a request stream.** Each poll diffs the new
  snapshot against the previous one via the T1 `Differ`; the first poll just seeds
  the baseline (no events). The screen states on-screen that these are "observed
  state transitions (no per-request stream — pending observability)". The live
  request feed from the brief mockup is a later swap when the observability source
  lands.
- **Sparklines are measured, not invented.** `Metrics.record(snapshot)` each poll;
  the sparkline plots total slugs / live slugs / fleet size — labelled "counts the
  TUI measured — not rps". No fabricated throughput.
- **Pause = stop polling.** `space` toggles `self.paused`; `poll()` early-returns
  while paused (proven by a pilot test: register + `r` yields no event when paused).
- **No-TTY → the `Card`.** A live feed has no meaning in a pipe, so the fallback is
  the current-state card (same choice as topology).

## 4. Gotcha worth remembering (markup vs literal brackets)

`[a]ll` / `[s]lugs` / `[PAUSED]` in a Rich-markup string get parsed as **style
tags** and stripped — the filter hint rendered as "ll lugs leet…". Fix: use
parentheses `(a)ll (s)lugs …` and `⏸ PAUSED` instead of literal `[..]`. Caught by
eyeballing the render (the pure tests asserted on the pre-render string, which still
contained the text — a reminder that string-content asserts don't catch
markup-rendering bugs; eyeball the rendered output). **Good failure.**
