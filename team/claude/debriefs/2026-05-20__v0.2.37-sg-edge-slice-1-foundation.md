## 2. TL;DR for the next agent

1. **The 05/20 SG/Edge briefs were written by an agent without deep codebase
   knowledge.** They describe AWS primitives in the abstract. The plan at
   `team/comms/plans/v0.2.37__sg-edge/README.md` re-grounds every component onto
   the **existing `sg aws *` surface** — read it before writing any Slice 2+ code.
2. **Almost everything already exists.** `sg aws cf` (incl.
   `CloudFront__Origin__Failover__Builder` and `CloudFront__Function__AWS__Client`),
   `acm`, `dns` (full Route 53 CRUD incl. TXT), `ec2`, `iam`, `lambda_`, `s3`,
   `logs` cover the AWS work. `sg_compute_specs/vault_publish/` is the proven
   Waker analogue to model the Edge Waker on.
3. **Only ONE genuinely-new AWS primitive:** `If-None-Match` on
   `S3__AWS__Client.put_object` (today it has `IfMatch` only). That is the boot
   lock. Slice 2.
4. **No SSM.** There is no `sg aws ssm` module. `vault_publish` polls readiness
   over HTTP; we do the same against `/_edge/health`. Keeps the proxy IAM role
   free of `ssm:*`.
5. **This slice is AWS-call-free.** Pure Type_Safe data + the shared TXT
   composer/parser. Lives at `sg_compute_specs/edge/`.

## 4. Failure analysis

- **GOOD failure:** First test run flagged that Safe_Str fields defaulting to
  `= None` stringify as `'None'`, not `''`. Caught immediately by the
  `test_defaults` assertions; fixed by defaulting to `= ''` (the Elastic-schema
  convention) and `Safe_Int__Port()` for the port field (its `min_value=1`
  rejects 0). No silent acceptance of a wrong default.

## 6. Realignment to the 2026-05-20 brief rewrite (`647de5a`)

After Slice 1 first landed, dev received a substantial brief rewrite (commit
`647de5a`, merged here) plus the v0.1.17 waker→`Serverless__Fast_API` refactor and
a new `fast-api/` architect-to-dev brief set. The foundation was realigned in the
same branch:

- **Module renamed `edge/` → `sg_edge/`** (doc 01 decision #2: matches the
  `vault_app` / `vault_publish` sibling naming). All classes re-prefixed
  `Edge__`/`__Edge__` → `SG_Edge__`/`__SG_Edge__`.
- **S3 lock removed.** The rewrite states "There is no S3 lock" — the Edge Waker
  is convergent (reads DNS, reconciles). So:
  - Dropped the planned `if_none_match` addition to `S3__AWS__Client` (no longer
    needed — **good thing it was caught before that code was written**).
  - Replaced `Schema__Edge__Fleet__State` (modelled as the S3 lock object) with
    `Schema__SG_Edge__State__Record` (the `_state.<parent>` TXT counter:
    `zero_streak` + `updated`) and added `SG_Edge__State__Builder`.
  - Dropped `List__Safe_Str__IP__Address` — fleet membership is the
    `proxies.<parent>` A records in DNS, not a blob field.
- **Phase 1 decisions updated** in the plan: plain HTTP CF→proxy (no proxy cert),
  no sidecars, static proxy count, asymmetric DNS cache TTLs, nginx-level log
  redaction, `Serverless_Fast_API` X-API-Key proxy↔target auth.
- **Edge Waker is a FastAPI Lambda.** Read all four `fast-api/` briefs; the
  concrete in-repo template is `vault_publish/lambdas/waker/` (Fast_API__Waker +
  routes/Routes__Waker + lambda_entry + waker__config) and the combined-deps
  loader at `sg_compute/_for_osbot_aws/`. Slice 3 builds the Edge Waker on this.

Test count after realignment: **32** (added `SG_Edge__State__Builder` tests).
