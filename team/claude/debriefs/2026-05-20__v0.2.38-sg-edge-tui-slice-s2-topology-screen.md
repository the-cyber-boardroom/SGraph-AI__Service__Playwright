# v0.2.38 SG/Edge TUI — Slice S2 (Topology screen)

## 1. Why

"How is the edge wired?" — the layered flow browser → wildcard → proxy fleet →
slugs, made interactive. Idiom #3 (Topology / Wiring Map). It is the `sg edge local
check` diagram reborn as a live, navigable screen.

## 2. What landed

| Piece | Where | Note |
|---|---|---|
| Pure render | `tui/screens/SG_Edge__TUI__Topology__Render.topology_markup(snapshot, selected_index)` | layered flow + slug rows + ▸ selection marker + Selected detail line; no textual → 3.11 |

pass, 6 skip, 1 pre-existing fail (waker needs `osbot-fast-api-serverless`). No mocks.

## 3. Key design decisions (the how)

- **Selection state lives in the screen; render is a pure function of it.**
  `topology_markup(snapshot, selected_index)` is pure; ↑/↓ just change the index and
  redraw from the cached snapshot (no re-fetch — fast, and decouples navigation from
  polling). Clamping keeps the cursor in `[0, len(slugs)-1]` and survives a refresh
  that changes the slug count.
- **No-TTY fallback reuses the `Card`.** The T1 `Card` already draws the same
  layered browser → wildcard → fleet → slugs shape, so it *is* the static topology —
  no separate plain renderer needed (unlike S3, whose diff has no Card equivalent).
- **Enter → S4 deferred, not faked.** The brief wants Enter to open the Slug-detail
  screen; S4 isn't built, so Enter is unbound for now and the Selected detail line
  previews what S4 will deep-dive. Documented, not stubbed with dead UI.
- **Same pattern as S1/S3.** Thin screen + pure render + shared glyphs + `asyncio.run`
  pilot tests. The pattern is now stable across three screens.

## 4. Gotchas / notes

- **Arrow-key bindings**: Textual binds `down`/`up` (plus `j`/`k`) to custom
  `select_next`/`select_prev` actions; the pilot test drives them with
  `pilot.press('down'/'up')` and asserts the clamp at both ends.
- The render highlights the selected slug with a `▸` + `[bold]` on the (pre-padded)
  label, so markup never throws off column width.

## 5. What's next

**S4 (Slug detail)** — honest skeleton: State + DNS sections real; instance / cost /
activity = pending Slice 5. Wire Topology's Enter to launch it once it exists.
Then **S5 (Events)** — uses the T1 `Differ` + `Metrics`. Then T-chain (`diagnose`,
Dockerfile locale, help overlay `?`, theme toggle, OSC-52 export) + the guide.

- **Good failures (surfaced, fixed):** a convoluted/meaningless test assertion on the
  ▸ marker (caught on self-review, replaced with a clear `Selected: <slug>` check).
- **Bad failures:** none. Enter→S4 is deferred (no dead UI), instance data stays a
  pending pane.
