# v0.2.38 SG/Edge TUI — Slice S3 (Local vs Edge comparison)

## 1. Why

The highest operational-value screen (per the plan and the human's read): "what's
different between the local edge and the AWS edge?" It is also one of the most
honestly buildable, because local and AWS are both real, queryable sources today.
Matches idiom #6 (Comparison / Drift) in the new TUI idiom catalogue.

## 2. What landed

| Piece | Where | Note |
|---|---|---|
| Pure render | `tui/screens/SG_Edge__TUI__Compare__Render` (`compare_markup` / `compare_plain`) | snapshot×2 → string; uses the T1 `Comparison` service; **no textual → testable on 3.11** |

## 3. Key design decisions (the how)

- **The only two-source screen.** S3 takes a `local_source` AND an `aws_source`,
  calls `snapshot()` on each, and feeds both to `Comparison.compare()`. Everything
  else (the seam, the glyph vocabulary, the thin-screen + pure-render split,
  `asyncio.run` pilot tests) is the S1 pattern reused.
- **Honest two-way only.** No "Deployed" column, no version matrix — out of scope
  for `sg_edge` (locked decision). A row is IN_SYNC when both sides agree (present
  *or* absent); LOCAL_ONLY / EDGE_ONLY name the side that has it.
- **`styled` flag, one renderer.** `compare_markup` / `compare_plain` are thin
  wrappers over one `_render(..., styled)` so the Textual view and the no-TTY plain
  diff never drift apart. The plain path has zero Rich markup (asserted in tests).
- **Drift summary line.** Counts differences split local-only/edge-only + an in-sync
  tally, with a `●`/`⚠` lead glyph — status at a glance (playbook §5).

## 4. Gotchas / notes

- **Two snapshots, one timestamp.** The header stamps from the local snapshot's
  `captured_at`; the two reads are a few ms apart — fine for operational drift.
- **AWS side needs creds in real use.** `sg edge tui compare` reads the live
  `edge.sg-labs.app` zone, so it needs DNS read access; the no-TTY test injects an
  in-memory AWS source via `_compare_sources_factory` (no creds).
- The new **TUI playbook + idiom catalogue** (dev `library/dev_packs/v0.2.36__tui-startup-pack/`)
  arrived mid-slice and confirmed the approach (thin-over-primitives, honesty rule,
  semantic colour). Worth reading before S2/S4/S5.

## 5. What's next

**S2 (Topology)** — the `check`-style layered diagram, interactive, `Enter` on a
slug node opens S4. Then **S4 (Slug detail)** — honest skeleton (State + DNS real;
instance/cost/activity = pending Slice 5), and **S5 (Events)** — uses the T1
`Differ` + `Metrics`. Then T-chain (`diagnose`, Dockerfile locale, help overlay `?`,
theme toggle, OSC-52 export) + the guide. All reuse the render-module + glyph +
pilot-test pattern.
