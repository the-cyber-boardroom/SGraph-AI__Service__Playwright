## 1. What SG/Edge is (the why), in three sentences

SG/Edge is a **scale-to-zero central edge tier** in front of vault targets:
**CloudFront + wildcard ACM → an OpenResty proxy fleet → vault backends**,
coordinated by an **Edge Waker** with **DNS-as-registry** state and **no
coordination service** (convergent reconciliation, no lock). It exists because the
per-vault TLS model didn't scale as `sg-compute` became a serverless environment
hosting many ephemeral workloads — SG/Edge terminates TLS centrally, routes by
slug, and scales independently of any one vault. The whole spec is **purely
additive**: nothing outside `sg_compute_specs/sg_edge/` imports it, except the one
intended `add_typer` line that wires `sg edge` into the top-level CLI.

## 4. Key design decisions (the how — and the non-obvious bits)

- **DNS-as-registry, no coordinator.** Three record types per parent:
  `proxies.<parent>` A (fleet membership), `_state.<parent>` TXT (`zero_streak`
  teardown counter), `_sg.<slug>.<parent>` TXT (routing). The reconciler reads DNS
  ground truth and converges; racing invocations cost one extra proxy that
  idle-teardown reclaims. No S3 lock, no DynamoDB, no SSM.
- **Two records per slug, two wakers.** `<slug>.<parent>` A = "registered" and
  `_sg.<slug>` TXT = "has a live backend" — both written by the **Vault Waker**
  (Phase 2). The proxy's decision tree: A+TXT → serve; A only → dormant (loading
  page, wake the vault); no A → not-recognised (404).
- **Edge Waker = `Serverless__Fast_API` Lambda**, mirroring
  `vault_publish/lambdas/waker/`. Routes are thin; all logic is in the reconciler.
- **Phase 1 proxy is plain HTTP**, `:80` public static short-circuit + `:8089`
  VPC-private management (`/_edge/health|version|stats|slug_seen`). The `:8089`
  split (brief 02) keeps `slug_seen`/`stats` off the public CloudFront origin.
  Access log omits `$remote_addr` (redaction at source).
- **Hard-coded zones** (`local/sg_edge_local__config.py`): `edge.sg-labs.app` is
  the default AWS edge parent for every `sg edge` command (the
  create/destroy-at-will distribution + Route 53 zone); `edge.sg-labs.local` is the
  local stack's zone.
- **Reconciler returns Type_Safe schemas** (`Schema__SG_Edge__Reconcile__Result`,
  `Schema__SG_Edge__Idle__Result`) so routes can `.json()` them (rule #6). Watch:
  `reconcile()` scales **up** only; scale-down is `idle_check()`'s job.
- **CLI test-injection without mocks.** Each CLI module exposes a module-level
  factory hook (`_dns_factory` / `_reconciler_factory` / `_stack_factory`) that
  tests assign to inject an in-memory/file-backed backend. Not `unittest.mock` —
  real implementations, swapped via a documented seam.
- **Local stack reuses everything.** `Local__Route53__Client` is a
  `Route53__AWS__Client` subclass with a JSON-file-backed boto-alike, so the *same*
  `SG_Edge__DNS__Helper` / `SG_Edge__TXT__Builder` run unchanged. State persists to
  `<state_dir>/dns.json` + `stack.json` so each CLI process sees the prior one's
  writes. `Local__Edge__Stack` plays *both* wakers; `Local__Edge__Proxy` is the
  Python equivalent of the (future) OpenResty Lua hot path.

### Gotchas the next session will hit
- **httpx 0.28** removed `AsyncClient(app=…)` — use Starlette `TestClient` over
  `waker.app()` (note: `app` is a *method*).
- **`rich.Console` soft-wraps** long lines and corrupts JSON — emit `--json` with
  builtin `print()`, never `c.print()`.
- **A missing local DNS zone** (before `setup` / after `teardown`) makes
  `list_records`/`get_record` raise `ValueError` — the stack guards `status()` /
  `registered_slugs()` / `unregister()` and the proxy treats it as not-registered.
- **`sg edge status` shows `desired: 0` in Phase 1** — `desired_target()` is driven
  by active vault slugs (`_sg.*` TXT), which only the Vault Waker writes (Phase 2).

## 6. How to run it

```bash
# tests
python3.12 -m pytest sg_compute_specs/sg_edge/tests/      # 157 pass
python3.11 -m pytest sg_compute_specs/sg_edge/tests/      # 94 pass, 63 skip

# the local edge (no AWS, no docker) — see the user guide for the full walkthrough
sg edge local setup
sg edge local register alice
sg edge local request alice          # → 200 "Welcome to the alice vault"
sg edge local check                  # ASCII diagram + deviations
sg edge local usecase all            # 6/6 scripted end-to-end use-cases
sg edge local teardown --yes
```

Note: in this CI container, `typer`/`rich` and `osbot-fast-api-serverless` are not
installed by default — `python3.12 -m pip install typer rich --break-system-packages`
to run the CLI suites locally; the FastAPI suite needs the serverless stack (py3.12).
