## The ask

Let `sg va create --with-playwright …` control the tags created in AWS —
specifically a **prefix** on the instance's tags.

## What I found

The vault-app tag set is built by the shared `EC2__Tags__Builder.build()`:
`Name`, `Purpose`, `StackName`, `StackType`, `CallerIP`, `CreatedBy`, plus the
vault-app extras (`StackWithPlaywright`, `StackEngine`, `TerminateAt`,
`StackTLS`, `StackTlsHostname`, `AccessToken`).

Key insight that made this safe and small:

- The `Name` tag is set to the **bare** stack name — there was **no**
  controllable prefix (the `Stack__Naming(section_prefix='va')` helper exists
  but only feeds the security-group GroupName, not the Name tag).
- `list`/`info`/`delete`/`connect` filter on **`StackName`** and **`StackType`**
  tags (verified in `EC2__Instance__Helper.find_by_stack_name` /
  `list_by_stack_type`) — **never** the `Name` tag. So a Name-prefix is purely
  cosmetic and cannot break any lifecycle command.

## The change (scope: vault-app only)

- `Schema__Vault_App__Create__Request.name_prefix : str = ''`.
- `Vault_App__Service.apply_name_prefix(tags, stack_name, name_prefix)` — a pure
  mapper that rewrites only the `Name` tag to `<prefix>-<stack-name>` via
  `Stack__Naming(section_prefix=prefix).aws_name_for_stack()` (reuses the
  never-double-prefix rule). Blank/whitespace prefix → no-op. Applied right after
  `tags.build(...)` in `create_stack`.
- `Cli__Vault_App`: `--name-prefix` option + `_set_extras` sets (and strips) it.

Deliberately did **not** touch the shared `EC2__Tags__Builder` — the prefix is
applied in a vault-app-owned post-step so no other spec's tagging changes, and
the logic is a pure list→list function unit-testable without AWS.

Example: `sg va create --name-prefix acme` → `Name=acme-warm-bohr`, while
`StackName=warm-bohr` / `StackType=vault-app` stay intact.

## Good failures

- **Checked the filter keys before assuming safety.** Confirmed
  `find_by_stack_name`/`list_by_stack_type` key off `StackName`/`StackType`, not
  `Name`, so the cosmetic prefix is provably side-effect-free for lifecycle ops —
  rather than trusting that "Name is just cosmetic."
- **Reused `aws_name_for_stack`'s never-double-prefix rule** instead of naive
  string concat, so re-running with an already-prefixed stack name is idempotent
  (covered by `test_prefix_never_doubled`).

## Bad failures

- None introduced. The pre-existing
  `test_serve_with_proxy_wraps_stock_boot` failure (a spacing-assertion mismatch
  that ships red on `origin/dev`) is unrelated and untouched.

## Addendum — `--name-prefix` also stamps a `Namespace` tag

Operator asked: can `--name-prefix` "prefix all tags"? Audited every tag first.
**It can't, safely** — the lifecycle commands resolve instances by an exact
server-side EC2 tag filter in the *shared* `EC2__Instance__Helper`:

- `sg va list` → `tag:StackType=vault-app` + `tag:Purpose=ephemeral-ec2`
- `info`/`delete`/`connect`/`check`/`wait`/`logs`/`stop`/`start`/`recreate`
  → `tag:Purpose=ephemeral-ec2` + `tag:StackName=<name>`

Prefixing those keys/values (or all keys) makes the filters match nothing →
every lifecycle command stops finding the stack. And several "descriptive" tags
are read **back** by value: notably **`StackEngine`** (the operator's suggested
"safe" example) drives podman detection (`engine == 'podman'`), so
`StackEngine=acme-docker` would silently force docker-mode on podman stacks.
`StackTLS`/`TerminateAt`/`AccessToken`/`StackTlsHostname`/`StackWithPlaywright`
are likewise read back; `CallerIP`/`CreatedBy` are data/identity.

**Safe realization (chosen):** `apply_name_prefix` now (1) prefixes `Name` and
(2) stamps an **additive `Namespace=<prefix>` tag** (`TAG_NAMESPACE`, non-filter)
so the operator can filter the console by `Namespace=acme`. Every other tag is
deliberately untouched. `Namespace` is documented as "never a lifecycle filter".

### Good failure (addendum)

- **Audited read-back before prefixing.** The operator's example tag
  (`StackEngine`) turned out to be read back for podman detection — surfaced the
  contradiction instead of prefixing it and silently breaking podman stacks.
  `test_data_and_filter_tags_never_prefixed` locks `StackEngine=docker` (not
  `acme-docker`).

## Follow-ups
