## Two operator asks

1. **Tag duplication.** `--name-prefix` should make the namespace visible across
   *all* tags, not just `Name` — accepting it's "a bit of a hack".
2. **Drop mitmweb, use mitmdump.** The mitmweb UI isn't needed, and `docker logs`
   on the mitmweb container was empty (mitmweb routes its event log to the web UI,
   not stdout), making the interceptor impossible to debug.

## Change 1 — prefixed-key tag duplicates

`Vault_App__Service.apply_name_prefix` now, on top of the `Name` prefix + additive
`Namespace=<prefix>` tag, appends a **prefixed-KEY duplicate of every tag**
(`<prefix>-StackType=vault-app`, `<prefix>-StackName=sleek-newton`, …). The
**originals are kept verbatim**, so:

- lifecycle filters (`tag:Purpose` / `tag:StackName` / `tag:StackType`) still match,
- read-back values (`StackEngine` → podman detection, `StackTLS`, `AccessToken`, …)
  are unchanged,
- the duplicates are purely additive and never filtered on.

Net: ~14 base tags → ~28 (well under AWS's 50-tag limit). Tests assert both the
duplicate (`acme-StackType=vault-app`) and that canonical lookups still resolve to
the unprefixed originals.

## Change 2 — mitmweb → mitmdump

`Vault_App__Compose__Template` agent-mitmproxy command:
`mitmdump --listen-port=8080 --set block_global=false --set termlog_verbosity=info
--set flow_detail=1 --scripts=/interceptors/active.py`.

**Why it matters:** `mitmdump` streams script-load errors + one line per request to
**stdout**, so `docker logs` / `sg va logs --source mitmproxy` finally show activity
(the whole reason the operator couldn't tell if the interceptor loaded). `mitmweb`
kept all of that in its web UI event log.

Cleaned up the now-dead mitmweb affordances (they pointed at a `:8000` admin
FastAPI that **only the custom `agent_mitmproxy` image has** — the vanilla image
vault-app runs never had it, so these were already broken):

- removed the `mitmweb` target from `_FORWARD_TARGETS` + `open` help,
- removed the `mitmweb`/`mitmweb-cookie` rows from `sp vault-app info`,
- mapper stops populating `mitmweb_url` / `mitmweb_ssm_forward` (schema fields kept,
  default `''`), dropped the dead `MITMWEB_LOCAL_PORT`,
- updated the `mitmproxy` log-source description to reflect streamed flows.

## Good failures

- **Diagnosed the empty-logs report correctly before changing anything:** the
  blank `docker logs` was mitmweb-by-design (event log → web UI), not a wiring
  failure — which is exactly what made mitmdump the right fix.
- **Spotted that the mitmweb UI affordances were already dead** (admin `:8000`
  belongs to the custom image, not the vanilla one vault-app runs) — so removing
  them is pure cleanup, not a regression.
- **Kept tag originals when duplicating** — verified the lifecycle filters/read-backs
  stay intact (`test_originals_kept_alongside_duplicates`).

## Bad failures

- None introduced. Pre-existing `test_serve_with_proxy_wraps_stock_boot` (red on
  `origin/dev`) untouched.

## Follow-ups

- `--tag KEY=VALUE` arbitrary tags (still owed).
- `flow_detail` could be made tunable (`--mitm-verbosity`) if request-line spam is
  too noisy on busy stacks.
- A `set-interceptor`-over-SSM command (hot-reload, no recreate) is now even more
  attractive since mitmdump logs the reload to stdout.
