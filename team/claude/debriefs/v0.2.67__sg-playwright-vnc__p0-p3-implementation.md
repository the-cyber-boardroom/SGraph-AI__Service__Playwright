## Failure classification (rule 27)

**Good failures** (surfaced early, informed design):
- The whole jlesage arc: SECURE_CONNECTION 307 → noVNC sub-path breakage →
  certutil NSS boot hang. Each was live-diagnosed, each traced to the same root
  (foreign image), and together they justified the step-back that produced this
  plan. The failures are documented in the superseded v0.2.65 plan's status line.
- The base manifest job's `pattern: digest-*` artifact download would have
  silently merged VNC digests into the BASE image manifest — caught while
  reading the pipeline before editing (hence the `vnc-digest-*` prefix).

**Bad failures** (implicit follow-ups):
- The `boot-ok` firefox-prep tolerance shipped (508fb10) and was deleted days
  later in P0 — code written against a symptom whose root cause (jlesage) was
  about to be removed wholesale. Cheaper to have stepped back first.
- This sandbox couldn't run docker, so P1's image has never actually been BUILT —
  the first `force_image_rebuild` CI run is the real P1 exit test. If the
  ubuntu-noble novnc/websockify packages misbehave, supervisord.conf is where
  it shows up.
