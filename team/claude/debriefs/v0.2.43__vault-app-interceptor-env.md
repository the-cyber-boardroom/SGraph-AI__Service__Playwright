## The ask

Operator noticed the vault-app mitm setup couldn't pass env vars to the
interceptor script — confirmed by comparing to the other specs.

## Cross-spec research (the gap)

| | Firefox | VNC | vault-app (before) |
|--|---------|-----|--------------------|
| script flag | `--scripts …/active.py` | `--scripts=…/active.py` | `--scripts=/interceptors/active.py` |
| script mount | `…/interceptors:/interceptors:ro` | same | same |
| **env → mitm** | **`env_file: /run/sg-firefox/env`** (operator `env_source`) | none | **none** ← gap |

Firefox writes an env file to the host and mounts it via compose `env_file:` on
the mitmproxy service, so the interceptor reads config from `os.environ`. VNC
doesn't need it (self-contained loggers). vault-app's use case (a
`fastapi_interceptor`) is the Firefox shape, so it needs env vars.

## The change (vault-app only)

- `Schema__Vault_App__Create__Request.interceptor_env : str` — resolved dotenv content.
- `Vault_App__Compose__Template`: `env_file: - /opt/vault-app/interceptors/active.env`
  on the agent-mitmproxy service.
- `Vault_App__User_Data__Builder.render_interceptor_block(source, env)` — **always**
  writes `active.env` (empty placeholder when none, `chmod 600`) before `compose up`,
  so the compose `env_file:` reference always resolves (a missing env_file is a
  hard compose error; an empty one is fine).
- `Vault_App__Service.create_stack` passes `request.interceptor_env`.
- CLI: `--interceptor-env-file <file>` (dotenv, read at CLI time) + repeatable
  `--interceptor-env KEY=VALUE` (List[str]); merged in `_set_extras`. KEY=VALUE
  without `=` and a missing env file both raise `typer.BadParameter`.

Confirmed the generic `Spec__CLI__Builder` supports `List[str]` repeatable options
(smoke test) before committing to that shape.

## Good failures

- **Always-write-the-env-file insight.** First instinct was to add `env_file:`
  only when env vars exist — but compose hard-errors on a missing env_file, and
  the interceptor block runs unconditionally in the with-playwright shape. Writing
  an empty placeholder (mirroring the no-op `active.py`) keeps the compose valid in
  every case. Caught by reasoning through the empty-stack path, not at boot.
- **Verified List-option support up front** rather than assuming the builder
  handled repeatable flags — a 10-line typer smoke proved it before the wiring.

## Bad failures

- None introduced. The pre-existing `test_serve_with_proxy_wraps_stock_boot`
  spacing failure (red on `origin/dev`) is unrelated.
