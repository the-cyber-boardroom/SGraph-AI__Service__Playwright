## 5. Failure classification (CLAUDE.md §27)

### Good failures (surfaced early, caught by tests, informed design)

- **`sg-tool-api` not published on the CDN (404).** Discovered during P5 — the shared `sg-tool-api` web component the pack assumed (Decision #1/#8) is not actually published. The console fell back to a **contract-compatible in-page `window.__tool` registration** (same surface, no CDN dependency) and `sg-layout` loads CDN-absolute as a graceful shell. Surfaced early, kept the agentic surface, did not block the slice. The prefix-aware test now guards that the fallback stays prefix-safe.
- **D7 — W2 gallery `wait_for` url_pattern glob is rejected.** Writing the body-level parse guard caught that W2's step `{"action":"wait_for","url_pattern":"**/dashboard**"}` (the correct Playwright `wait_for_url` glob, per brief 02) is **rejected with HTTP 400** by `/sequence/execute`, because `Schema__Step__Wait_For.url_pattern` is typed `Safe_Str__Url__Permissive` (`Schema__Step__Wait_For.py:20`) whose regex requires a full `http(s)://...` URL. Confirmed end-to-end through the in-memory TestClient (status 400, `ValueError: ... Safe_Str__Url__Permissive ... does not match required pattern`). This is a real gallery-vs-schema contract bug. **Flagged, not fixed** — it needs either a schema field-type change or a gallery edit, both runtime/design decisions outside the P6/P7 tests-and-docs scope. It is asserted AS A CONTRACT in `test_Workflows__Gallery__Bodies.py::test__D7__W2_url_pattern_glob_is_rejected_by_wait_for_schema` (the same good-failure style brief 06 uses for W7's allowlist) so the day it is fixed, a test turns red and points the next agent at it.
- **D1 — reality-doc staleness.** The reality doc + `CLAUDE.md` said "16 direct endpoints" and "`Routes__Session` removed in v0.1.24", but the code wires both `Routes__Inspect` (`Fast_API__Playwright__Service.py:110`) and `Routes__Session` (`:111`) → 21 direct endpoints. The pack had pre-flagged D1 for the Librarian (README sign-off). Fixed in the reality doc + catalogue this slice; the load-bearing `CLAUDE.md` line is flagged for the human (§7) rather than silently edited.

### Environmental quirks (worked around, not silenced)

- **Python 3.11 vs 3.12.** The default `python` is 3.11 and cannot import the stack; tests run via `.venv312`. Known.
- **Route-scan tests fail in this venv.** 10 pre-existing unit tests that scan `app().routes` for `.path` fail (empty path) for environmental reasons — verified they fail on untouched files too, so not a regression. New P6 tests deliberately use the render pattern (`Routes__Index().index(_FakeRequest()).body.decode()`) and TestClient instead of route-scan, so they pass.

### Bad failures

- None introduced. D7 is a pre-existing latent bug surfaced (good), not silenced.

## 6. How the Docker checks gate the publish

The existing `.github/workflows/ci-pipeline.yml` already has the right shape: `build-amd64`/`build-arm64` (`:122`,`:180`) push **by digest only**; `integration-test-image` (`:254`) runs the live suite against the by-digest image and **gates** `push-playwright-manifest` (`:400`, `needs`/`if` at `:404-405`). Per brief 06 §6 / README Q5, P6 **extends `integration-test-image`** rather than inventing a new job:

- New module `tests/integration_live/test_99_ui_console.py` is collected by the suite that job already runs.
- The "Run remaining live integration suite" step (`:335-340`) now `--ignore`s `test_99_ui_console.py` so it is not sharded across xdist workers.
- A new dedicated step **"UI console + Docker-image checks (gate the publish)"** runs `pytest tests/integration_live/test_99_ui_console.py -v` right after, serially. Because it is a step inside `integration-test-image`, a red check fails the job → `push-playwright-manifest` is skipped → no manifest tag. A broken console never gets published.
