# v0.2.38 SG/Edge TUI — Slice S1 (Deployment Reality screen)

## 1. Why

First exploratory Textual screen, riding the T1 data layer. Answers "what is
deployed right now?" visually instead of as a wall of CLI text. It also establishes
the **pattern every later screen follows**: a thin Textual app over a pure render
module over the snapshot seam.

## 2. What landed

| Piece | Where | Note |
|---|---|---|
| Pure render | `tui/screens/SG_Edge__TUI__Deployment__Render.deployment_markup()` | snapshot → Rich-markup string; **no textual/rich import → testable on 3.11** |
| Shared glyphs | `tui/screens/widgets/SG_Edge__TUI__Glyphs` | slug-state / severity / yes-no → (glyph, style); pure, reused by later screens |
| Textual screen | `tui/screens/SG_Edge__TUI__Screen__Deployment` | thin `App`: polls source, drops markup into a `Static`, timer refresh; `q`/`r` bindings |
| CLI command | `tui/cli/Cli__SG_Edge__Tui` (`deployment`) | lazy textual import; `--target local\|aws`; **no-TTY → static `Card` fallback** |
| Wiring | one `add_typer(_tui_app, name='tui')` in `cli/Cli__SG_Edge.py` | the single intended external touch |
| Tests | `tui/tests/test_*` (render, screen pilot, cli) | 32 total |

Tests: **3.12 → 32 pass** (incl. 3 Textual pilot + 2 CLI); **3.11 → 27 pass, 5 skip**
(pilot + CLI gated on textual/typer, render + T1 run). Existing `sg edge` CLI
registration tests still pass (the new `tui` sub-app is additive). No mocks — pilot
tests inject a real in-memory `Local_Source` over a temp stack.

## 3. Key design decisions (the how)

- **Content/​view split.** All Screen-1 content is a pure function
  (`deployment_markup`) tested on 3.11; the Textual class only wires the source to a
  `Static` and binds keys. This is the Type_Safe-vs-framework carve-out in practice
  and keeps the testable surface off Textual.
- **Textual is lazy + gated, never load-bearing.** `Cli__SG_Edge__Tui` imports the
  screen *inside* the command body, so `add_typer` in `Cli__SG_Edge` never pulls
  textual — the whole `sg edge` CLI works without it. View-layer tests `@skipUnless`
  textual, exactly as the CLI suites gate on typer.
- **No-TTY fallback reuses T1's `Card`.** Piped / CI / broken-chain → a static ASCII
  card, then exit. Falls out of the snapshot seam for free; safe to pipe.
- **Honest pending panes.** Instance ids / vault servers render
  "pending Slice 5" lines — never fabricated. The capabilities seam from T1 makes
  this the natural thing to do.
- **`asyncio.run()` pilot tests.** Avoids a `pytest-asyncio` dependency: sync test
  methods wrap an `async` scenario driving `App.run_test()` (`pilot.press`/`pause`).

## 4. Gotchas the next session will hit

- **Single-command Typer collapses.** A Typer app with exactly one command treats it
  as the root callback, so `tui deployment` fails with exit 2. Fixed with a no-op
  `@app.callback()` (forces group behaviour). Harmless once more screens land, but
  keep the callback.
- **Textual 8.x is the installed line** (`8.2.7` here). `App.run_test()` +
  `Pilot.press/pause` are the test surface; `set_interval` drives refresh.
  `refresh_seconds=0` disables the timer in tests.
- **Bind `q` to a custom `action_leave`**, not the built-in `quit`, so the test can
  assert `app.exited` deterministically.
- Deps in the web container: `pip install --break-system-packages textual typer rich`
  (plus the T1 set) to run the full suite on 3.12.

## 5. What's next

Per the plan, **S3 (Local vs Edge)** next — it has the `Comparison` service ready
and is the highest operational value. Then S2 Topology, S4 Slug detail, S5 Events
(uses `Differ` + `Metrics`), then T-chain (`diagnose`, Dockerfile locale, help
overlay, theme toggle, OSC-52 export) + the guide. Every screen reuses the
render-module + glyph + pilot-test pattern S1 established.

- **Bad failures:** none. AWS-target actions remain unwired (S1 is read-only/​local
  for mutations); live AWS instance data stays a labelled pending pane.
