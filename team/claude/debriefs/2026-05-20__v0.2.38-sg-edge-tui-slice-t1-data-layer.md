# v0.2.38 SG/Edge TUI — Slice T1 (shared data layer)

## 1. Why (in three sentences)

The SG/Edge TUI plan (`v0.2.38__sg-edge-tui`) reframes the work as five
exploratory screens over **one shared data layer**. T1 is that layer: a single
normalised snapshot, two sources (local + AWS-DNS), and the pure services
(Differ / Metrics / Comparison / Card) the screens will render. It is built first
because it is pure, runs on 3.11 with no Textual dependency, and de-risks every
screen that follows.

## 2. What landed

| Piece | Where | Note |
|---|---|---|
| Normalised snapshot | `tui/schemas/Schema__SG_Edge__TUI__Snapshot` | source-independent; carries `capabilities` (real panes) + reuses `List__SG_Edge__IP` / `List__Local__Edge__Issue` |

Tests: **3.11 → 22 pass; 3.12 → 22 pass.** No Textual, no typer, no FastAPI in the
T1 path. Rest of the `sg_edge` suite unaffected (the one unrelated failure,
`test_invoke_health`, needs `osbot-fast-api-serverless`, absent in this container).

## 3. Key design decisions (the how)

- **One snapshot, two sources, one builder.** `SG_Edge__TUI__Snapshot__Builder.build()`
  takes a `SG_Edge__DNS__Helper` + target + parent + optional deployed flag. Local
  injects a helper over the file DNS (deployed = stack marker); AWS injects one over
  real Route 53 (deployed = zone presence). Local and edge therefore render
  *identically* — the snapshot seam the plan asked for. No screen ever touches a
  primitive directly.
- **`capabilities` makes "no data yet" first-class.** `REAL_CAPABILITIES` =
  TOPOLOGY/SLUGS/CHECKS/FLEET. Cost/throughput/instances are deliberately *absent* —
  a screen renders a labelled pending pane, never a fabricated number. This is the
  no-fabrication rule encoded in the type.
- **Honest events & sparklines.** The Differ emits only observed state transitions
  (registered / went-live / went-dormant / removed / fleet / issue / cleared);
  Metrics plots counts it measured itself. No rps/cost series exist.
- **AWS is read-only until Slice 5.** `AWS_Source.can_act()` is False and its
  mutation methods raise `NotImplementedError` — screens disable the keys. Reads
  (topology/fleet/slugs/checks) work against the live DNS registry today.
- **Issue vocabulary reused, rules re-homed.** The snapshot reuses
  `Schema__Local__Edge__Issue` / `Enum__Local__Edge__Severity`, but the deviation
  rules live in the builder (source-agnostic: no stack-marker concept), so AWS and
  local get consistent findings. `Local__Edge__Stack.check()` stays the CLI's own
  thing — the TUI never calls it.

## 4. Gotchas the next session will hit

- **`get_record` raises on a missing zone.** The builder guards with
  `find_hosted_zone_by_name` before any `get_record` (same trap the local stack
  documented). A missing zone → "not provisioned" snapshot, not an exception.
- **Deps not installed in the web container.** `osbot-utils` / `osbot-aws` /
  `pytest` are absent by default — `pip install --break-system-packages …` to run.
  The T1 path needs only those three (plus the in-repo `tests/unit/.../Route53__AWS__Client__In_Memory`).
- **`datetime.utcfromtimestamp` is deprecated** — the Card uses
  `fromtimestamp(ts, timezone.utc)`.
- **Textual is NOT a T1 dependency.** Keep it that way: the screens (S1–S5) are the
  only place Textual enters, and those test suites should `@skipUnless` it like the
  CLI suites gate on typer.

## 5. What's next (the screens, per the plan)

Sequence by real-data-richness: **S1 Deployment → S3 Compare → S2 Topology →
S4 Slug detail → S5 Events**, then T-chain (diagnose / Dockerfile locale / no-TTY
fallback) + the new guide `library/guides/v0.2.38__sg-edge-tui-guide.md`. Every
screen reads `SG_Edge__TUI__Data_Source.snapshot()`; S3 uses `Comparison`, S5 uses
`Differ` + `Metrics`, the export key uses `Card`.

### Failure classification (per CLAUDE.md §27)
- **Good failures (surfaced, fixed):** a `datetime` deprecation warning (caught by
  running the suite, fixed to timezone-aware); missing-`requests` made unrelated CLI
  tests fail (correctly diagnosed as an env gap, not a regression — installing it
  cleared them).
- **Bad failures:** none. AWS mutations are deliberately unwired (raise + `can_act`
  False), documented as Slice 5, not silenced.
