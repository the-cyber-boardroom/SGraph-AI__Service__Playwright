## 3. Key design decisions (the how)

- **Focus tracked by name, not index.** The screen remembers `focus_name`; a refresh
  re-finds it (or falls back to the first slug if it vanished). ↑/↓ recompute the
  index from the name, so navigation survives slug list changes between polls.
- **DNS derived from `state`, no schema change.** The TUI snapshot slug carries
  `state` (not `has_a`/`has_txt`), so the render derives them: A present ⇔
  state∈{LIVE,DORMANT}; TXT present ⇔ state∈{LIVE,ORPHAN_BACKEND}. Backend ip:port
  is the only "vault binding" that's real; the source/article/working vaults are
  Phase-2 pending.
- **Drill-in via exit-and-relaunch (not nested apps).** These screens are standalone
  Textual `App`s (per the plan); you can't cleanly push one App inside another. So
  Topology's Enter records `opened_slug` and exits; the CLI's `topology` command,
  after `.run()`, launches the Slug-detail App for that slug. Honest drill-in UX;
  the limitation (no "back to topology") belongs to the canonical composite app.
- **Same pattern, fourth time.** Pure render (+`styled` flag for the no-TTY plain
  variant) + thin screen + shared glyphs + `asyncio.run` pilot tests.

## 4. Gotchas / notes

- **`enter` binding.** Textual binds `enter` to a custom `action_drill`; the pilot
  test drives `pilot.press('down','enter')` and asserts `app.opened_slug`.
- The CLI relaunch (topology → slug) isn't pilot-tested (it launches a second real
  App), but both halves are: Topology sets `opened_slug` (pilot) and Slug-detail
  renders for a given name (pilot + pure).
